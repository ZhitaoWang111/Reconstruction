1.1 · 增量式场景理解 Harness

当前输入方案 v2 · 2026-09-24 · 历史视觉证据按需查看

窗口开始时只发送当前 5 帧的完整 RGB 和 mask overlay，共 10 张图（不足 5 帧时按实际帧数）。全部历史 Object 以文字记录、全局 3D 框和最近空间候选提供，不预先发送历史图片。每条当前观测最多列出 3 个最近历史 Object；候选不限定归属，不是类别结论或置信度。

02术语与状态

2.1 · 一条观测不等于一个跨帧物体

版本化方案：v2 · 历史图片按需查看（2026-09-24）。本页维护当前语义；子页记录该版输入、工具行为与执行流程。早期输入修订和历史运行回放保留各自版本含义。

本节按 2026-09-24 当前方案核对；旧轮次保留当时设想，当前能力以本节为准。命名规范：InstanceRecognition/src/harness/naming-conventions.txt。

术语当前含义与边界
observation · 观测一帧中的一个原始 mask 及其元数据与三维观测点；ID 如 0000:001。同一物体可对应多帧、多条观测。
category_label / mask_id前者是上游给这条观测的类别提示，不保证正确；后者如 M01，只标识当前帧中的 mask。overlay 显示 mask 编号和 bbox，类别仍在结构化元数据中。
object / object_id / object_label跨帧维护的实体、稳定编号（Object1 等）、为实体选定的类别。类别相同不证明身份相同，类别不同也不证明是两个物体。create 设置初始 object_label；核对视觉证据确认旧类别有误后，relabel 可修正 object_label。原始观测的 category_label 保留。
语义组当前按原始 mask 粒度维护身份。有视觉证据支持、且上游有意整体分割的一对或一组，可作为一个语义组实体保留；仅凭类别词不能确定分组。意外混入无关物体的 mask 应标 repair。当前没有独立 group 数据类型或成员拆分工具。
pending / defer / repairpending 是所有未归属观测的汇总；defer 表示判断证据不足，repair 表示 mask 需要修复。它们是观测的状态，不是物体的状态，均不参加物体点云融合。
3D 占据点云当前实际维护的是已归属观测的可见表面点融合，不是完整实体体积或不可见表面的恢复。

3.6 · 执行约束与实现边界

执行约束：哪些是程序强制检查，哪些只是提示要求？

程序检查：基础版本、可访问证据编号、非空理由、有效目标和观测；同一提案中观测只能出现在一次 assign/defer/repair 中；事务结束后 cutoff 之前的每条观测都须有 assigned/defer/repair 状态，每个保留物体须有观测。未变化的历史记录不必重复提交。

提示要求：判断需有相关视觉证据、解释实际可见线索、避免无证据的身份拆分或合并。代码不验证语义结论是否正确，也不证明理由真实；格式合法不代表识别准确。

取证顺序：inspect 返回的图像放在随后一条带 tool_call_id 的 user 消息中；等待图片后再提出依赖它的判断，不能在同一模型响应中一边请求图像一边提前决定。compare_geometry 仅返回几何数据，不提供图片或身份判定。

提案生命周期：每次 propose_update 都清空旧待提交提案，即使新提案校验失败；commit_update 只能提交最近成功校验的提案。ready_to_commit 只是工具内部标记，正式成功由 run.py 返回 committed。

尚未实现：delete、mask 像素拆分或自动修复、任意几何编辑。relabel 已支持修正物体的 object_label，不是修改观测的 category_label 或物体编号。同一物体的部件观测可直接 assign 同一实体；部件与整体需要分别维护时，也分别作为有观测的 Object 处理；不能创建没有观测的整体父对象。

调用频率：这些工具属于按窗口运行的 Harness。工具在本地执行，结果再交给 GPT，才进入下一轮模型判断；不是每个 mask 固定调用一次 GPT，也不能把“6 个工具”理解为“每窗固定调用 6 次 GPT”。
