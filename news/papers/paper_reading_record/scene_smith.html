SceneSmith: Agentic Generation of Simulation-Ready Indoor Scenes

这篇工作把室内场景生成定义成“从自然语言到可直接进入物理仿真的机器人环境”的问题，而不只是生成视觉上合理的 3D 房间。

核心定位文本条件的层次化 agent 系统，联合生成房屋/房间布局、家具、小物体、碰撞几何与物理属性。

1. 研究背景和动机

论文的出发点是家庭机器人训练和评测需要大规模、多样、可交互的仿真环境，但现有室内场景往往停留在稀疏家具布局或视觉真实感层面。真实家庭包含密集小物体、可开合家具、层级支撑关系和物理约束；这些恰恰是机器人抓取、移动和任务执行最容易失败的地方。

作者认为，已有方法通常把“资产生成”和“场景生成”拆开做：资产方法重视单个物体的几何和物理属性，场景方法则多假设固定资产库，只生成布局或摆放关系。SceneSmith 想把二者合在一起：用户输入自然语言环境或任务描述，系统自动生成房间级或房屋级场景，并保证每个对象尽量是可分离、可操作、带碰撞几何和物理参数的 simulation-ready asset。

任务定义

  • 输入：自然语言场景描述，或由机器人任务进一步扩展出的场景提示词。
  • 输出：包含建筑结构、家具、墙面/天花物体、可操作小物体，以及对象姿态的室内场景。
  • SimReady 要求：资产带 visual geometry、collision geometry、质量、质心、惯量、摩擦，articulated object 还需要关节定义；场景需要减少穿模并在重力仿真下保持稳定。
  • 目标边界：论文展示的是自动生成与仿真评测管线，不等同于证明真实机器人部署成功；策略评测也使用示例 model-based policy，而非端到端通用机器人策略。
阅读判断：这篇应归入 SimReady 重建/生成方向。它不是 NeRF/3DGS/VGGT 那类纯视觉重建，也不是只做单物体资产，而是面向机器人仿真的室内场景构造系统。

2. 研究方法

层次化场景构造

SceneSmith 把场景表示为房间集合，每个房间包含建筑几何和对象集合。生成过程是一棵树：先由 layout agent 生成房屋/房间结构，再按房间分支独立放置家具、墙面物体和天花物体，最后再针对桌面、柜子、架子、地面区域等支撑实体生成 manipuland 分支。这样做的好处是上下文规模可控，并且每个局部分支仍能继承全局 prompt 的约束。

Designer / Critic / Orchestrator 三元 agent

  • Designer 负责通过工具修改场景，例如创建房间、生成资产、摆放家具、调整位姿、构造组合小物体。
  • Critic 只能观察和验证，给出语义合理性、物理可行性、prompt 对齐等评分与自然语言反馈，从而降低 designer 自评偏差。
  • Orchestrator 调度 designer 与 critic，决定接受、继续修改、终止或回滚。若 critic 分数下降，系统可以回到检查点并要求换一种方案。
  • Agent 通过结构化状态查询、渲染观察、碰撞/可达性检查、资产获取等工具与场景交互。每个 agent 保留当前和上一轮完整上下文，早期轮次压缩成摘要，视觉观察用滑动窗口保存。

资产生成、检索与验证

静态物体主要走 text-to-image-to-3D：用 GPT Image 1.5 生成参考图，用 SAM3 分割前景，再用 SAM3D 重建带纹理网格；随后标准化朝向、缩放到目标尺寸，并补充碰撞几何和物理属性。可开合家具和设备则从 ArtVIP 检索，因为作者明确指出当前 text-to-3D 还不能可靠地产生适合机器人仿真的铰接结构和运动学。

资产路由器会把复合请求拆成可独立操作的原子对象，例如 fruit bowl 拆成 bowl 和多个 fruit；它还会按阶段过滤不合适对象，选择生成、铰接检索或 thin covering。生成或检索出的资产经过网格完整性检查和 VLM 语义验证，验证项包括物体类型、风格一致性、单物体性、完整性、比例合理性以及门/抽屉是否闭合。失败资产会在重试预算内重新生成或重新检索，仍失败时把原因反馈给 designer。

物理可行性与导出

系统使用 Drake 做 simulator-in-the-loop 构造。家具和小物体阶段之后，先用非线性优化把对象平移到最近的无碰撞位置，约束为 Drake signed distance 大于 1e-5 m，方向保持不变；随后在重力下仿真，让对象落到静态稳定状态。墙面和天花物体被 welded 到世界坐标，因此不走同样的自由体后处理。

场景原生表示为 SDFormat + Drake model directives，并可导出 MJCF、USD；导出保留 visual geometry、collision geometry、物理属性和 articulated joints。Blender 导出用于可视化，只包含视觉几何。

机器人策略评测应用

论文还把生成场景接到自动策略评测：给定任务描述，LLM 先生成多样场景 prompt，并保证必须物体存在且初始状态尚未完成目标；SceneSmith 生成场景后，示例 KUKA LBR iiwa14 移动底座策略执行 pick-and-place；最后 evaluator agent 结合对象列表、距离、支撑关系和多视角渲染判断任务是否成功。这个设计减少手写 success predicate，但作者也承认会牺牲一定确定性。

3. 实验设计和结果

评测设置

主评测使用 210 个 prompt，其中 179 个是 room-level，31 个是 house-level。Room-level prompt 覆盖 SceneEval-100、稀有房间类型、物体密度、主题风格等类别；house-level 只和 Holodeck 比较，因为基线中只有 Holodeck 支持多房间。外部基线包括 HSM、Holodeck、I-Design、LayoutVLM 两种资产库版本、SceneWeaver。消融包括 NoCritic、NotGenerated、NoAssetValidation、NoSpecializedTools、NoObserveScene、NoAgentMemory。

机器人策略评测结果

作者在 4 个 pick-and-place 任务上各生成 25 个场景，共 100 个场景。任务包括 fruit 到 plate、coke can 到 table、cup 到 sink，以及跨房间的 water bottle 到 living-room coffee table。人工标注 300 个评测状态后，evaluator agent 与人工判断一致 299/300，唯一分歧是水果落在盘子边缘的人类/agent 判定差异。标准策略总体 16/100，退化策略 12/100，论文据此说明自动评测能区分策略质量，但绝对成功率并不高，因此这部分更像评测管线验证，而不是强策略展示。

代价、失败案例与证据边界

  • 生成成本：SceneSmith 平均每个场景 $13.98，耗时 3:26；Designer 占成本 75.9%，Critic 占 20.0%。NoCritic 降到 $4.24 和 1:40，但对象数从 71.1 降到 54.0。
  • 资产失败：验证器会拒绝类型错误、风格不符、复合物体未拆分、缺件、比例异常或开门/开抽屉冻结的资产；但对文字标签、金属/透明材质，以及检索资产的细节匹配更宽松。
  • 物理失败：堆叠、填充容器、局部排列和 pile 工具都可能因碰撞、掉落或越界失败，并把失败对象和穿透深度反馈给 agent；后处理还会移除倾倒家具或离开支撑面的 manipuland。
  • 评测边界：SceneEval 是 VLM-based，论文明确提到存在 false positive/negative；基线原本不具备完整 SimReady 属性，作者为公平比较给它们补了碰撞几何和物理参数，因此物理指标反映的是补齐后场景在 Drake 中的可行性。
  • 能力边界：当前 text-to-3D 不可靠生成铰接结构，所以 articulated object 仍依赖 ArtVIP 检索；evaluator agent 能处理开放任务，但判定含糊空间关系时仍可能和人工不一致。
总的判断：SceneSmith 的强项不是“重建真实扫描场景”，而是把文本到场景生成推进到机器人仿真可用的资产级完整性。它的贡献集中在层次化 agent 编排、生成/检索混合资产管线、物理后处理和自动策略评测闭环。
