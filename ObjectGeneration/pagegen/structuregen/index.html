    3.0
    门窗分工
    11-19 定
    
      
    东西归谁墙体这一步怎么做
    
        
    墙上的洞上游交接只开交接测到的洞（本场景 int_3 一个），agent 不自己开洞
    
        
    门扇实例物体生成（DualCraft）不做；门的位置保持实墙
    
        
    窗（玻璃、窗扇、窗套）实例物体生成不做；窗的位置保持实墙，也不画窗套
    
        
    门套墙体 agent交接洞口四周的门套由 sg.frame 做
    
        
    踢脚线、腰线墙体 agentsg.strip
    
      
    
      
    关着的门、玻璃窗在交接里本来就是实墙，所以墙体这一步保持封闭。门扇与窗由实例生成放到墙前面；以后需要穿过门，在组装阶段按门的包围盒开洞。

    工具一览
    
      
    agent 能用 7 个工具。look 和 get_scene_info 合在一张卡片里。
    
      
    
        
    
          
    ① 看compare(frame)自定义
    
          
    想换一张照片核对时调用。每次改动后程序已自动给一张，不用重复调用。
    
          
    
            
    输入
    frame关键帧号，必须是当前这面墙的关键帧之一
    
            
    输出（agent 收到什么）
    • 一张图：左边照片，右边同一相机、同样尺寸的当前模型（平光 + 墙角遮蔽 + 细轮廓线：大面积墙色就是设定色，只在墙角略暗，墙角、洞口和饰线描细边）
    
            
    规则 / 检查
    • 只读，不改场景
    • 只出图，不给 RGB、色差、亮度差或合格判断
    
          
    示例compare(447)
    
        
    
        
    
          
    ① 看（可选）look · get_scene_infoMCP 原生
    
          
    想从别的角度看模型，或查物体、材质的名字和尺寸时用。
    
          
    
            
    输入
    look: mode / views / target从哪看、看哪些物体
    get_scene_info: query / fields查哪些物体、要哪些字段
    
            
    输出（agent 收到什么）
    • look：一张图
    • get_scene_info：物体清单文字
    
            
    规则 / 检查
    • 只读，不改场景
    
          
    示例look(mode="angles", target=["ext_E_1"])
    
        
    
        
    
          
    ② 想declare(n, findings)自定义
    
          
    动手前写下判断。每一项都会变成带编号的待办，结束这面墙时逐项核对。
    
          
    
            
    输入
    n墙段序号，必须是当前这面墙
    findings.surface墙面颜色、材质、粗糙度、依据帧号
    findings.trims[]踢脚线 / 腰线 / 门套：高度、沿墙范围、颜色、依据帧号；没有就给空列表
    findings.notes可选：看到但这一步不做的东西，如门、窗、柜子
    
            
    输出（agent 收到什么）
    • 待办清单，如 t1 墙面、t2 腰线
    
            
    规则 / 检查
    • 每项都要有依据帧号
    • 重复调用会更新待办；已完成且内容没变的项保留状态
    • 门扇、窗、窗套不接受
    
          
    示例declare(3, {surface: {…, basis: [894, 447]}, trims: [{kind: "腰线", …}]})
    
        
    
        
    
          
    ③ 做execute_blender_code(code, description)MCP 原生，经 harness 转发
    
          
    唯一能改模型的工具，正常情况下只调用下面三个 sg 算子。
    
          
    
            
    输入
    codeBlender Python 代码
    description一句话说明这次改了什么，写进编辑日志
    
            
    输出（agent 收到什么）
    • print 输出或报错
    • 新的场景版本号
    • 自动检查的问题清单和待办进度
    • 最正对帧的对比图
    
            
    规则 / 检查
    • 没有 declare 就拒绝执行
    • 执行前存整场景快照
    • 检查规则见 3.3
    
          
    示例execute_blender_code('bpy.ops.sg.paint(seg="ext_E_1", face="front", rgb=(…), item="t1")', "上墙面色")

    收尾commit()自定义
    
          
    所有墙和照片看不到的面都做完后调用，全场景总检查。
    
          
    
            
    输入
    无
    
            
    输出（agent 收到什么）
    • 通过：进入第 4 步导出
    • 未通过：指明哪面墙、哪个面有问题
    
            
    规则 / 检查
    • 重跑全部硬检查
    • 列出未收敛的墙和未解决的待办
    
          
    示例commit()
    
        
    
      
    
      
    sg 算子：在 execute_blender_code 里调用的三个函数
    
      
    在 Blender 启动时预先注册。做成算子是因为 MCP 安全模式不允许 import 自定义模块，但允许调用 bpy.ops.*。
    
      
    算子作用参数结果
    bpy.ops.sg.paint给墙的某一个面上色、设材质
    seg 段名
    face front / back / top / end_start / end_end / reveal
    rgb 颜色，0–255
    roughness 粗糙度 0–1，可选，默认 0.9
    item 对应的待办编号；依据从 declare 读取
    		这个面的材质被替换，依据写进物体属性
    bpy.ops.sg.strip在 front 面加水平长条，做踢脚线或腰线
    seg 段名
    z0, z1 下沿、上沿离地高度（米）
    a0, a1 沿墙范围（米），可选；碰到洞口自动断开
    depth 凸出墙面，≤ 0.05 m
    rgb 颜色
    item 对应的待办编号
    		贴墙长方体，作为这一段的子物体
    bpy.ops.sg.frame沿交接洞口加一圈门套
    seg 段名，必须有交接洞口
    width 门套面宽（米）
    depth 凸出墙面，≤ 0.05 m
    sides front / back / 两面
    rgb 颜色
    item 对应的待办编号
    		洞口左、右、上三条木条，作为子物体；不画窗套
    
    
    

    
    
      
    3.3
    验收
    
      
    自动检查
    
      
    检查项每次改动后finish_segment不通过时
    代码执行报错查—自动回滚
    墙体几何被改（顶点、体积与白模不一致）查再查自动回滚
    改到了其他墙段查再查自动回滚
    出现不是 sg 生成的新物体查再查自动回滚
    饰线越界、穿过洞口、与他段相交、尺寸超范围（凸出 ≤ 5 cm，踢脚线高 2–30 cm）查再查保留并报告；不修正不能结束
    朝房间的面缺材质或依据报告进度必须通过不能结束
    declare 的待办未完成报告进度完成，或写明放弃原因不能结束
    
      
    commit 重跑全部硬检查；第 4 步导出的 USD 还要能被 pxr 读回并通过校验。
    
      
    
        
    到达上限时
    这面墙回到最后一个没有硬问题的版本，标“未收敛”
    缺材质的面填中性色，依据标“未完成”
    交付保留已有结果，并列出未解决项
    不放宽几何不变、不改其他墙段、饰线不越界
    
        
    质量（离线评估，不卡交付）
    颜色每个关键帧比较渲染与照片的 ΔE，不给 agent
    人工审阅页：12 帧「照片 | 最终模型」+ 每面墙的 declare
    过程每面墙回复数、未收敛墙数、token 与费用
    
        
    预算
    每面墙最多 15 次模型回复
    收尾最多 15 次
    全场景最多 150 次
    总费用$20 保护线
    预估用满约 $15–18，需实测
    
      
    
    
    

    
    
      
    3.4
    从 DualCraft 借鉴
    
      
    机制DualCraft这里的做法
    
        
    差异账本差异带编号，逐项解决或放弃declare 生成待办，sg.* 用 item 关联
    
        
    不收敛处理同一项改 3 个版本未解决就退出同一待办改 3 次仍未完成，标“未收敛”，不再阻塞本面墙
    
        
    改前备份整场景备份，失败回滚照用
    
        
    改后反馈edit 后附预览改动后自动返回对比图和检查结果
    
        
    每轮提示注入剩余回合和场景版本注入第几面墙、未解决待办、剩余回复数
    
        
    空转恢复连续无动作先提醒，第 3 次停止照用；第 3 次结束这面墙并标“未收敛”
    
        
    验证令牌validate 发令牌，commit 校验不用：改动后自动检查，finish_segment 现场再查
    
        
    对比数值附平均色和亮度差不用：compare 只出图；模型用平光 + 墙角遮蔽 + 细轮廓线
