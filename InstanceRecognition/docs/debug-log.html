00怎么用这一页

变更记录写问题和方向，不写实现细节——细节会随代码漂移，问题不会。结果 debug 写现象和实测数字， 问题未解决时不写编号，解决后再补 commit。

为什么只记这些。改动本身可以从 git log -p 读出来，但当时想解决什么 读不出来；结果的问题同样如此——界面上看到一处错，背后是哪一步造成的，事后很难重建。 这一页补的就是这两样。

待编号 Problem 01 · 两只「鞋」的点云几乎完全重叠 2026-11-04
现象

Object12（left gray shoe beside console）与 Object13 （right gray shoe beside console）在结果页选中后，两个点云和两个 OBB 基本重合， 肉眼分不出是两只鞋。

实测
  • 中心距 5.7 cm（1.551, 2.211, 0.152）vs（1.547, 2.268, 0.148）。
  • 包围盒几乎相同：A [1.33,1.89,0.08]–[1.77,2.55,0.23]， B [1.33,1.89,0.07]–[1.76,2.61,0.23]。
  • 2 cm 内互邻：A 的 41% 点、B 的 49% 点；5 cm 内：64% / 89%。
  • 中位最近距离 A→B 2.7 cm，B→A 2.0 cm。
  • 32 帧里两者同时出现（同一帧有两张 mask，各自归一个物体）。
待查
  • 这是一个物体被拆成两个，还是两只鞋本来就这么近？ GT 只有一个 shoes 物体（obj_0058，60 帧，43 点），但 GT 的物体粒度本身比 harness 粗， 不能直接据此判定。
  • 若是两只鞋：为什么点云重叠到这程度？两只鞋相距 5.7 cm 时，2 cm 体素 + 4 cm 中位反投影误差会让它们几乎无法区分。
  • 若是一个物体：create 在同一窗口被调了两次（都在 created_at: 4）， 当时模型看到的是同一帧的两张 mask，还是不同帧？
  • 参考位置：两者均在 (1.55, 2.21–2.27, 0.15)，与 console 相邻；同区域的 Object14（remote）和 Object9（printed sheet）也都在这个台面上。

4d95fa9 标签不再承担区分个体的职责 2026-11-04
要解决的问题
  • P6 加了一条规则「label 必须能指向唯一一个物体」，模型据此把「是哪一件」塞进 label。
  • 结果标签平均 1.8 词涨到 4.3 词，最长 13 词，41% 含相对位置短语（left shoe beside console）。
  • 这类标签是地址，所指物体一旦被 merge/relabel 就失效；也不符合下游 handoff 契约要的短类别词。
  • 追溯发现：P6 那条规则的目标（压掉重名）是真实的，v9 的 17 个同名物体却全是正确命名——四只鞋、三处插座、四幅画。
改动方向
  • 把「是什么」与「是哪一个」拆开：label 只说类别，1–3 词。
  • 同类多实例允许同名，区分交给 object_id；指名道姓写进 reason。
  • 保留 P6 里对的半句：一个 Object 是一件实体，不是一类。
  • 代码零改动——state.py 从不检查标签唯一性。
