SceneAssembly · Reference · scenesmith

scenesmith：组装是怎么做的

它从一段文字生成可仿真的室内场景，没有真实照片可对照。 每个阶段都是同一套三角色结构：designer 用工具摆放，critic 只读并打分，planner 负责轮转和回滚。 模型给粗略位置和关系，贴合由工具算；每个阶段结束后用"去穿插投影 + 重力仿真"兜底。

00总览

五个阶段依次执行 · 和我们相关的是家具和小物件两个阶段

01
户型
输入 文字描述  →  输出 墙、门窗、地面
02
家具 agent
输入 空房间  →  输出 落地家具，每件只有 x、y、yaw
03
家具后处理
输入 家具布局  →  输出 去穿插投影 + 重力仿真之后的布局；倾倒超过 45° 的家具被移除
04
墙面物体 agent、天花板物体 agent
结构相同，这一页不展开
05
小物件 agent × 每件家具
输入 一件家具的支撑面  →  输出 面上的小物件；每件家具摆完做一次局部的投影 + 仿真
06
最终后处理
输入 整个场景  →  输出 家具固定，只让小物件移动的投影 + 仿真
模型
决定放什么、大致放哪、和谁有关系（椅子朝向桌子、衣柜背靠墙）。还负责评审和打分。
工具
把粗略位置变成精确接触：定朝向、推到刚好碰上、落到支撑面、校验占地和净空。物理检查的结论优先于看图。
和我们的差别
它是生成，不是重建：可以删物体、换更小的资产、加随机扰动，用主观评分判断好坏。我们有照片，物体集合是定死的。可借鉴的是工具设计、验收结构和物理处理。

01阶段与表示

RoomScene · 每类物体只能由对应的 agent 修改

场景
RoomScene：房间几何（墙、地面、门窗）加一组物体。可以整体序列化成字典再恢复，回滚靠这个。
物体
位姿、视觉网格、碰撞体（凸分解后的 SDF）、包围盒、缩放系数。小物件另记"在哪个支撑面上、面内坐标和旋转"。
类型
家具、墙面物体、天花板物体、小物件。每个 agent 只能改自己那一类；物理检查也只把它能改的违规报给它。
资产
按文字描述现场生成（SAM3D 或 Hunyuan3D），或从库里检索。入库前统一姿态和尺寸，见下。

资产入库前的三步 放置阶段因此只需要 yaw

01
VLM 看多视图
顶视、底视和若干侧视，每张带编号和坐标轴  →  哪个轴朝上、哪张图是正面、材质、质量
02
转到统一姿态
上 = +Z，正面 = +Y，底面在 z = 0，水平居中
03
按期望尺寸等比缩放
designer 生成资产时必须给 [宽, 深, 高]。三个轴各算一个缩放系数，取中位数，整体等比缩放
为什么等比
源码注释：图生三维的网格比例大体可信，绝对尺度未知，所以只定尺度、不改比例。这和 LiteReality 三个轴分别缩放正好相反。

02三个角色

base_stateful_agent.py · designer 和 critic 各有独立的持久会话

角色能用的工具看得到什么推理强度
planner选摆放风格 · 请求初始设计 · 请求评审 · 请求修改 · 回滚designer 的总结、critic 的意见和评分变化low
designer全部修改工具 + 观察 + 物理检查 + 待办清单自己的全部历史high
critic只读：观察、读场景状态、朝向核对（小物件阶段没有朝向核对）场景本身。看不到 designer 的对话high
物理结果直接注入
critic 不调用物理检查。每次评审前由 harness 算好，把结果写进它的指令里，保证 critic 和 designer 看到的是同一份。
原文转达
planner 被要求把 critic 的意见原样转给 designer，不过滤、不加自己的提醒。
防止停下来问
planner 的提示词专门处理一种情况：designer 或 critic 回了"要不要我继续？"而没有干活。这时不进入下一步，而是再叫同一个角色一次，让它直接执行。

03评审与回滚

一个阶段内的循环 · 家具最多 3 轮 · 小物件每件家具最多 2 轮

planner
选摆放风格：natural 或 perfect
决定之后每次放置加多大的随机扰动
designer · 初始设计
观察空房间 → 列待办 → 生成资产 → 逐件放置 → 物理检查
提示词要求：有任何碰撞都不许结束
harness · 评审前
算物理违规（家具阶段还算通行性）
结果写进 critic 这一次的指令
critic · 独立会话 · 只读
观察 → 读物体列表 → 用工具核对朝向 → 写意见 + 打分
  • 家具 6 项，小物件 5 项，每项 0–10：真实度、功能性、布局、完整度、提示词符合度（家具多一项通行性）
  • 有任何物理碰撞，真实度最高 4 分
  • 还有严重问题时，只许提严重问题，不许夹带优化建议
  • 工具结论优先于看图：朝向核对说不对，就是不对
harness · 存检查点
场景状态 + 评分，保留最近两份
把评分变化附在意见后面，一起交给 planner
评分变差 · 回滚
恢复上一份检查点
触发条件：任一项下降 ≥ 2 分，或总分下降 ≥ 1 分。
planner 被建议调用回滚，换一种改法
否则 · 继续修改
critic 的意见原文转给 designer
designer 只处理严重问题，改完再做物理检查，然后回到评审
结束
全部评分达标 · 轮数用尽 · 同一问题改了两次还在
达标线：家具 ≥ 9，小物件 ≥ 8。
结束时 harness 再评一次；如果比上一份检查点差，自动恢复上一份
回滚有两处
一处是 planner 自己决定调用，一处是流程结束时代码自动判断。后者不依赖模型记得去比较。

04家具：工具

furniture_agents/tools/ · 家具只有三个自由度

工具作用要点
generate_assets按文字描述生成一批家具每件必须给期望的 [宽, 深, 高]
add_furniture_to_scene_tool
move_furniture_tool		放置或移动参数只有 x, y, yaw。z 固定在地面，不能倾斜。落点必须在地面范围内。放置后按风格加一点随机扰动
snap_to_object_tool贴到另一个物体或墙上见 05
check_facing_toolA 是否朝向（或背向）B从 A 沿它的正面方向发一条射线，看是否穿过 B 的包围盒（只看水平面）。返回是否正确，以及应该转到的角度
rescale_furniture_tool等比缩放改的是资产本身，同一资产的所有实例一起变
remove_furniture_tool删除提示词里是解决碰撞的备选手段
get_current_scene_state读所有家具位置、旋转、尺寸、世界坐标下的包围盒
observe_scene渲染见 10
check_physics物理违规列表见 09
check_reachability房间是否连通按 0.3 m 宽的方形通行体检查，返回挡路的家具
随机扰动
natural：位置标准差 3 cm，yaw 标准差 1°；perfect：1 mm 和 0.1°。随机数的种子取自位姿本身，所以重放时结果一致。
统一缩放的后果
比例不对时，缩放修不了，只能重新生成。提示词明说：比例对、尺寸错用缩放；形状或比例错就重新生成。

05snap_to_object

scene_tools.py + snapping_helpers.py · 一次调用完成三件事

designer
snap_to_object(物体, 目标, orientation)
物体已经放在大致位置。orientation 取 toward、away 或 none
第 1 步 · 先解开穿插
如果两者已经重叠，沿水平方向保守推开
把物体按它的最大尺寸当成圆来算。这样下一步无论转到什么角度，都不会重新穿进去
第 2 步 · 定朝向
算出让物体正面朝向（或背向）目标的 yaw
目标是圆的（凸包体积不到包围盒的 80%），朝它的中心；
目标是方的，朝包围盒上离自己最近的点。none 时跳过这一步
第 3 步 · 推到接触
选方向，然后逐步移动直到碰上
  • 定过朝向：只沿物体自己的正面轴移动（toward 向前，away 向后），保住刚定好的朝向关系
  • 没定朝向：方向取两个网格最近点的连线
  • 目标有网格：每步 1 cm，用两者的碰撞体（凸分解）做碰撞检测，碰上就停
  • 目标是墙：按包围盒一步算出距离
结果
留 1 cm 的缝，写入新位姿
返回：原位置、新位置、移动距离、转到的角度。距离不到 1 mm 时直接报告"已经接触"
为什么逐步检测
源码注释：如果把顶点投影到移动方向上算距离，高处的顶点（比如桌面边缘）会挡住移动，即使下面是空的。用凸分解后的碰撞体逐步检测，椅子才能推进桌子下面。
为什么留缝
避免浮点误差让"刚好接触"在下一次物理检查里被报成 1 mm 的穿插。
角落要两次
放进角落要 snap 两次：第一次贴一面墙，第二次贴另一面墙并带 away。最终朝向由第二次决定。

06实例：椅子与衣柜

取自 designer 提示词里的示例调用 · 不是运行记录

椅子靠到餐桌边 类别 A：正面朝向目标

designer · 调用 1
add_furniture_to_scene_tool("dining_chair", x=3.0, y=5.0, yaw=0)
位置和角度都是估的，不要求准。得到 dining_chair_0
designer · 调用 2 → 工具执行
snap_to_object_tool("dining_chair_0", "dining_table_1", orientation="toward")
转到正面朝向桌子 → 沿正面方向每步 1 cm 往前推 → 碰到桌子停下，留 1 cm
designer · 调用 3
check_physics → observe_scene
物理检查没有违规，再看一眼渲染

提示词的说法：原来要"放置 → 核对朝向 → 改角度 → 贴合"四步以上，现在三步。

衣柜靠墙 类别 B：正面必须背向墙

designer · 调用 1
add_furniture_to_scene_tool("wardrobe", x=-1.5, y=3.0, yaw=90)
designer · 调用 2 → 工具执行
snap_to_object_tool("wardrobe_0", "wall_north", orientation="away")
转到正面背向北墙 → 向后推到贴墙。柜门朝向房间
critic · 之后的评审
check_facing_tool("wardrobe_0", "wall_north", direction="away")
不看图判断，用工具核对。提示词：柜门朝墙属于"家具无法使用"，功能性最高 3 分
这两个例子说明
designer 只需要知道"椅子朝桌子""衣柜背靠墙"这类关系。它给的坐标可以差几十厘米，角度可以完全不对，工具会补上。
不适用的情况
提示词禁止把茶几 snap 到沙发上：两者之间要留 0.3–0.5 m 的腿部空间。这种"应该有间距"的关系仍然靠 designer 自己给坐标，再用物理检查确认。

07小物件：逐件家具

stateful_manipuland_agent.py · 每件家具一组全新的三角色会话

VLM · 一次调用
哪些家具上要放东西
对每件选中的家具给出：建议放的物品（必须的和可选的分开）、提示词里的约束、风格说明
VLM · 一次调用
每件家具的上下文家具
2 m 内的邻居里挑出相关的，比如桌子周围的椅子。之后渲染时一起画出来，用来判断桌面物品该朝哪边
循环 · 对每件选中的家具
以下步骤重复一遍
harness
提取这件家具的支撑面
一个面都没有（比如植物）就跳过。见 08
新建 planner / designer / critic
和 03 相同的循环，最多 2 轮评审
会话是新的，不带上一件家具的历史。观察图只画这件家具、它上面的物体和上下文家具
harness · 这件家具的后处理
去穿插投影 + 5 秒重力仿真
只取"墙 + 地面 + 这件家具 + 它上面的物体"，家具固定。
下落超过 0.3 m 且落到地上的小物件被移除
写回
小物件的新位姿合并回完整场景
某件家具出错不影响其他家具：记日志，继续下一件
为什么逐件
两个原因：每件家具一个新会话，token 用量有上限；每次物理求解只涉及大约 7 个物体，比整场景 300 多个物体容易得多。
检查按家具过滤
处理某件家具时，别的家具上的小物件引起的碰撞不报给当前的 designer。

08支撑面与面内放置

support_surface_extraction.py + manipuland_tools.py · 高度不由模型给

从家具网格提取支撑面

01
按法向聚类
三角面按法向相似度和邻接关系分组，留下法向朝上的（z 分量 ≥ 0.95）
02
按高度拆分
同一法向但不同高度的面分开：书架的每层是一个面
03
定高度和边界
面的高度取顶点高度的高分位数，再抬高 1 cm，让物体放上去后靠重力落稳；边界取凸包
04
量净空
从面上的顶点向上发射线，打到家具自身就记下距离，取第 10 百分位。净空不到 5 cm 的面丢弃

放置

list_support_surfaces 返回每个面的 id、面积、高度、净空。然后：

place_manipuland_on_surface(asset_id, surface_id, position_x, position_z, rotation_degrees)
# 坐标原点在面的中心；x 是左右，另一个是前后；旋转绕面的法向
校验不通过时
落点在面的凸包内返回错误和原因，场景不变。
例："物体高 0.32 m，超过该面净空 0.25 m。请确认是不是选错了面。"
物体的凸包占地在面内。顶面先把占地缩小 5% 再判断，允许少量悬出；隔层不允许
物体高度不超过该面的净空

09物理

physics_validation.py + physical_feasibility.py · 检查给 agent 看 · 投影和仿真在 agent 之后兜底

check_physics：碰撞判定

方面做法
几何每个物体的碰撞体（凸分解）。检查时所有物体都设成自由体，这样固定的家具之间也会被查到
度量Drake 的成对有符号距离，只取负值（穿插）。同一对物体只报一次
阈值穿插超过 1 mm 就报
地面放宽到 5 cm
物体与自己所在的家具放宽到 2 cm，算作正常接触。其他任何一对都不放宽
其他违规挡住门的开合、堵死通道、超过墙高（都算失败）；挡窗（只警告）；地毯互相重叠或伸到墙下

投影 + 仿真

输入
agent 摆完的场景（或其中一件家具的子场景）
阶段 1 · 去穿插投影
带"最小距离"约束的优化，求最小的移动量
旋转固定，只动位置。物体很多时只把有碰撞的设成可动。
单个面上的版本还约束物体不出面的边界
阶段 2 · 重力仿真
让物体落稳，六个自由度都放开
每件家具后 5 秒；整场景 15 秒；步长 1 ms
清理
移除倒下或掉落的物体
家具：倾斜超过 45°。小物件：下落超过 0.3 m 并落到地上
输出
更新后的位姿
任何一步出错都退回输入的场景，不中断流程
何时范围谁能动
家具 agent 结束后整个房间所有家具
每件家具的小物件摆完后墙 + 地面 + 这件家具 + 它上面的物体只有小物件
全部结束后整个场景只有小物件
分工
check_physics 是给 agent 的反馈，要求它自己改到零碰撞。投影和仿真不经过 agent，是它没改干净时的兜底，也顺便把略微悬空的物体落到面上。
对重建的含义
它可以直接删掉倒下的物体。重建不能删，但"仿真前后位移了多少"本身是一个质量信号。

11上下文控制

图片是主要开销 · 三个机制

机制做法配置值
轮次裁剪只有最近的轮次保留完整内容和图片。更早的轮次去掉图片，文字部分可以用模型摘要成一段保留最近 1 轮；摘要开启
轮内裁剪同一轮里多次观察时，只保留最近几次的图片最近 2 次（小物件阶段）
重复调用拦截在最近若干次调用的窗口里，同一个调用（同名同参数）重复太多次就返回错误，并提示先刷新场景状态再试窗口 30 次，上限 25 次
加上逐件新会话
小物件阶段的上下文不会随家具数量增长：每件家具从空会话开始，只带这件家具的任务说明。
