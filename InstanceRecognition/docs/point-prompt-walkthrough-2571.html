perception_agent 怎样给一帧出 mask：以帧 2571 为例

帧 2571 就是 v14 里 Object064（电视柜）被拆碎的那一帧：现行的文本 prompt 流程在这里给了 11 个 cabinet mask。 下面按 trial3 的真实记录，逐轮展示 GPT（agent）、宿主和 SAM3 各做了什么。整帧 5 轮、73 秒、10 个 mask。

运行 tmp/point_prompt/runs/trial3/frame_002571 GPT gpt-6-sol · reasoning none SAM sam3.pt 交互式点提示 · 3 遍细化 轮数 5 prompt token 65,255 耗时 73 s

01三个角色

GPT
agent 本体。看图、决定分哪些物体、在哪里打点、哪些结果可以保留。每轮只能调用一个工具，看不到 mask 的像素，只能看宿主渲染的图和数字。
宿主
工具的实现方（tmp/point_prompt/run.py）。校验参数、调 SAM、把结果画成 GPT 看得懂的图、算 GPT 用眼看容易漏的事实（点是否在 mask 内、碎块、面积门槛、重叠），在 finish 时核对每个计划都有着落。
SAM3
只负责贴边。每组点 → 一个 mask：第 1 遍用点，第 2、3 遍把上一遍的 logits 作为 mask_input 再细化。不知道“一个物体”是什么。

02开局：agent 拿到什么

第一条消息只有两张图和一句话：系统 prompt（约 1150 词，定义“什么算一个物体”、SAM 怎么读点、工具和工作流程）+ 原图 + 每 100 px 一条网格线的同一帧。坐标就是原图像素，GPT 从网格上读。

03逐轮流程

每行一轮；左到右是一次工具调用的往返：GPT 发起 → 宿主处理（需要时调 SAM）→ 结果回到 GPT 进入下一轮

核对计划 → 写盘
检查 P1–P10 都已保留、没有既保留又跳过的。写出 masks/*.png（10 张二值 mask）、kept.jpg、result.json（每个物体的点、分数、bbox、面积）。

耗时是每轮 GPT 往返的时间（SAM 推理是毫秒级，可忽略）；token 是该轮请求的 prompt token。每轮请求都带着前面所有的图，所以 token 逐轮增长。GPT 每轮只返回工具调用，没有附带文字说明（reasoning effort 为 none），它的判断只能从调用参数里看出来。

04结果

05这一帧说明了什么

  • 粒度在 plan 就定下了。GPT 把柜子按整件列进计划，后面打点只是兑现这个决定。现行流程里根本没有这一步，粒度由 SAM 对 “cabinet” 一词的理解决定。
  • 多部件物体靠“每个部件一个点”。电视柜 7 个正点分布在上柜、立柱、开放格、下柜上，SAM 才把它当一个整体；负点把电视、书、相邻柜子切出去。
  • 这一帧的检查 / 修正环节没有被用到。两条警告 GPT 都接受了，没有重分、没有 combine、没有 zoom——10 个候选一次通过。在帧 2794 里同一个环节才真正起作用（分两次再 combine，减去书）。trial3 的 7 帧里，最少 4 轮（1397、3018：plan → segment → keep → finish），最多 7 轮（2794、559）。
  • 警告是证据，不是规则。宿主只报告事实，接不接受由 GPT 决定。这里的“碎成 3 块”从图上看是灯杆遮挡造成的，保留是合理的；但 GPT 没有说明理由（reasoning none 下它只输出工具调用），所以我们只能从结果判断它的决定对不对，看不到它为什么这么决定。
