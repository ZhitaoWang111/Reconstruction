InstanceRecognition · Pipeline Design · 1105-v1

从一张 RGB 图到一个跨帧物体

GPT 判断画面里有什么，SAM3.1 按这些判断切出 mask（过小的过滤掉）， 投影器把每个 mask 像素落成三维点并写入相机位姿， Harness 再逐窗口决定这些点属于哪个物体——每个物体最多持有 5 条观测， 每次提交后渲染反投影图让模型确认。

版本 1105-v1 核对源码 2026-11 投影策略 amb3r_per_frame_v1 Source scene_amb3r_v2 基准 v11 · 500 帧 / 100 窗

01SAM / GPT 出 mask

src/inference/label_frames.py · gpt_sam31.py · sam31_segment.py

输入
一批原始 RGB 帧（JPEG）。不含任何 mask、深度或时间上下文。
输出
每帧一组二值 mask PNG，外加一份把 mask 与类别、置信度绑在一起的 predictions.json。mask 是帧内局部的，没有跨帧身份。
命令
python -m src.inference.label_frames → python -m src.inference.gpt_sam31（顺序执行）

两步分工先 GPT，后 SAM

GPT 那一步只看图，说出画面里有哪些类别、每类该用什么提示词去分割。 SAM 那一步消费这些提示词，把文字落到像素上。两步分开是因为它们失败的模式不同： 类别判断错要换 prompt 重跑，分割错要换阈值或权重重跑，重跑范围不一样。

面积过滤1105-v1 新增 · DEFAULT_MIN_MASK_AREA_FRACTION = 0.005

在 SAM 候选循环里，mask 像素数计算后、预算截断前，过滤掉画面占比低于 0.5% 的候选（1296×968 帧约 6,273 像素）。 被过滤的候选不写 mask 文件，只记入 excluded_by_size（类别、面积占比、bbox、sam_score）。

500 帧实测：0.5% 阈值过滤 1154/5046 原始候选（22.9%），影响 341 帧。 主要丢弃：书 247、鞋 134、遥控 96、音箱 84、电灯开关 63。 已知代价：柜子丢 43 个、门丢 15 个（大物体的小视图）。若点云缺块先查 excluded_by_size 记录。

excluded_by_budget（按 SAM 置信度截断，上限 16 个/帧）和 excluded_by_size 互相独立， 后者发生在前者之前。500 帧实测中无帧触及预算上限（最大 16 个/帧），excluded_by_budget 几乎不激活。

500 帧实测规模

指标数值
原始候选（面积过滤前）5046 个
0.5% 过滤后保留3892 个（77.1%）
过滤影响帧数341/500 帧

02mask 投影到 3D

src/geometry/amb3r_mask_source.py · scene_amb3r_v2

输入
上一步的 mask + AMB3R metric_head 推理结果（逐帧点图 pts、置信图 conf、相机位姿 pose）
输出
每帧一份 frames/NNNN.npz（points_world、rgb、mask_bits、pixel_indices、grid_shape_hw、camera_to_world）；清单里附 intrinsic_color
命令
python -m src.geometry.amb3r_mask_source --output artifacts/sources/scene0000_00/scene_amb3r_v2

点云投影原理

AMB3R 对每个像素预测了一个三维位置（pts）和置信度（conf）。 mask 像素 → AMB3R 点图里对应位置的三维坐标 → 乘上 Sim(3) 变换到扫描坐标系 → 写入 points_world。 每帧恰好一个点，没有多射线歧义，也没有遮挡泄漏。

1105-v1 新增：相机位姿写入 source

AMB3R 的 pose（相机到 AMB3R 世界坐标的 4×4 矩阵）乘上同一份 Sim(3)， 得到相机到扫描坐标系的 camera_to_world（4×4），写进每帧 npz。 harness 可以直接读，无需重新拟合 Sim(3)。

RGB 相机内参（fx=1169.62, fy=1167.11, cx=646.30, cy=489.93, 1296×968）从 ScanNet 提取清单读取， 写进 source 的 manifest.json 的 intrinsic_color 字段，供 verify 阶段反投影用。

Sim(3) 来源

Sim(3)（scale 0.8875，R，t）由 fit_sim3_from_gt.py 拟合，用的是预测相机轨迹和 GT 相机轨迹之间的 Umeyama 对齐。 拟合后的变换记录在 pointcloud_gt_corrected_evaluation.json，source 里的 sim3_source 字段指向该文件。 这一步用了 GT 位姿——它属于离线校准，不在推理路径上。

scene_amb3r_v1（v11 所用）没有 camera_to_world，是 1105-v1 新建 scene_amb3r_v2 的原因。v1 保持原样，用于对照。

产物目录结构

scene_amb3r_v2/ ├── manifest.json 500 帧清单，含 intrinsic_color、sim3_source、bounds ├── frames/ │ └── NNNN.npz 每帧：points_world (K,3)、rgb (K,3)、mask_bits (K,)、 │ pixel_indices (K,)、grid_shape_hw (2,)、 │ camera_to_world (4,4)（新） └── assets/ ├── frame_XXXXXX.js viewer 用的 base64 点云资产 └── background.js 场景背景点云

03harness 框架

src/harness/ · 逐窗口的模型决策循环

输入
02 产出的 source 目录（每帧一份带位姿的三维点云）
输出
物体身份与归属（版本化状态）、每个物体的累计点云、可回放的页面
命令
python -m src.harness.run；已完成的结果用 --publish-only 只重建页面

到这里，数据是「每帧一堆带归属位的三维点」。还缺的是身份： 第 0 帧的椅子、第 3 帧的椅子、第 7 帧的椅子，是不是同一把。这件事由模型通过工具循环决定。

窗口

帧被切成固定大小的窗口（默认 5 帧）。每个窗口是一笔事务：模型看这一窗， 决定这些观测归给哪些物体，提交，进入下一窗。 开始时模型拿到的是当前窗口每帧的 RGB 与 overlay、每条观测的类别与几何摘要， 以及全部已归档物体的文字记录（含质心坐标）。

历史图片一开始不发。 只有文字与几何。要确认某个历史物体长什么样，模型得主动调 inspect_object 或 inspect_observations。

一个窗口的生命周期run.py

1
组装输入
inputs.build_window_content → 一条状态 text、逐帧「观测 text + RGB + overlay」、一条历史访问说明。 同时把本窗观测登记进可引用证据集，并写 window_inputs/NNNN_context.json 审计。
2
工具循环
最多 max_calls 轮。每轮模型调一个工具（parallel_tool_calls: false）。 工具返回的图片作为下一条 user 消息补进会话。
3
propose_update → verify
1105-v1 新增。提案通过结构检查后，宿主对 hold / create / merge 动作渲染反投影图； 返回 verify_required + 图。模型确认后 commit，或修改提案重新 propose。 verify 轮次独立计数（最多 2 轮），不占 max_calls。
4
预算警告
第 max_calls−2 轮之前插入。提示立刻提交；从这轮起 reid gate 放行。
5
提交与落盘
commit_update 成功才写盘。先写 versions/.NNNN.tmp，算完点云再原子改名； 写 checkpoint.json = {version, cutoff}。失败不碰旧版本。
6
耗尽即失败
用完 max_calls 仍未提交 → 抛错，检查点保持上一窗口。重跑命令从该窗口继续。

04窗口初始输入

src/harness/inputs.py · src/harness/spatial_context.py

一个窗口的初始输入（1105-v1） ├── 1. 窗口状态 一条 text 块，最先发送 │ ├── window [first, cutoff]、state.version、max_calls │ ├── spatial_candidates_policy 候选规则说明 │ └── 已归档物体档案：每个 Object 一条 │ ├── id、object_label、created_at、status（恒为 provisional） │ ├── label_history（发生过 relabel 才有） │ ├── observation_count 只给数量，不给观测 id │ └── centroid 持有观测点云的质心均值，3 个坐标（新） │ ├── 2. 当前观测 每帧 3 个块，逐帧发送 │ ├── text：sampled_sequence + observations，每条观测一条记录 │ │ ├── id（seq:instance）、seq、source_frame_id、instance_id │ │ ├── category_label 上游类别提示，不是物体身份 │ │ ├── bbox_xyxy、image_size_wh、overlay_color_rgb │ │ ├── point_count、centroid、bounds 反投影点云摘要 │ │ ├── bbox_truncated 新：bbox 是否触及画面边缘（≤5 px） │ │ └── spatial_candidates：至多 15 个 │ │ ├── object_id、object_label │ │ ├── gap_m 新：第 5 百分位最近距离（米） │ │ ├── overlap 新：10 cm 内点占比（0–1） │ │ ├── view_direction 新：相机到质心的单位向量（需 v2 source） │ │ └── camera_distance_m 新：相机到质心距离（需 v2 source） │ ├── image：完整原始 RGB │ └── image：全帧彩色 mask overlay │ └── 3. 历史访问说明 最后一条 text └── 只有文字档案；历史图片走 inspect_object / inspect_observations 按需取 与 v11 相比删除的字段： ✗ global_object_geometry（全局 OBB 块：center_xyz / size_xyz / axes_world） ✗ representative_observation_id（历史观测 id 暴露导致无效引用） ✗ observation_ids（同上） ✗ state.pending（deferral 不再广播）

空间候选重写spatial_context.py · 1105-v1 item 2

候选的候选物体点云只用该物体的持有观测（status held）构建，最多 5 条， 不再用所有历史归属。这消除了早期错误归属对点云的污染。

字段计算方式含义
gap_m 观测点云到候选物体点云各点最近距离的第 5 百分位 「还差多远才能接触」；第 5 百分位抑制 mask 边缘噪点
overlap 观测点云中距候选物体点云 10 cm 以内的点的比例 「有多少表面是共享的」；10 cm 容差吸收 AMB3R 跨帧误差（中位 6.6 cm）

候选选取规则：丢弃 gap > 2 m 的物体 → 按 gap 升序取前 8 → 若第 9 名起 gap < 0.5 m 则继续补入，上限 15 个。

体积变化：v11 窗口 51 首条消息约 122,696 字符（其中 state.pending 67,610 字符、global_object_geometry 约 22,000 字符）。 1105-v1 去掉这两块后，同等规模窗口预计在 30,000–40,000 字符，降幅约 65%。

05工具与动作

src/harness/tools.py · src/harness/state.py

四个工具

工具返回说明
inspect_observations(ids) 最多 4 条观测的 RGB + overlay 看当前窗口或历史观测的实际 mask 覆盖范围
inspect_object(object_id) 代表观测图 + 元数据 + geometry 摘要 返回物体的 centroid、bounds_min/max、size_xyz（持有点云计算，最多 5 条）。 可传 all_observations: true 返回全部持有观测（最多 5 条），每条附图； 适合想判断哪条持有观测应该被换出时用。
propose_update(proposal_json) proposal_id 或 verification_required 或 verify_required 提案通过结构检查后自动触发 verify； reid gate 返回 verification_required（历史物体未 inspect）； verify 返回 verify_required（反投影图待确认）。
commit_update(proposal_id) ready_to_commit 写盘并结束窗口；verify 检查在 propose 阶段完成，commit 不再检查。

持有上限与换位HOLD_LIMIT = 5

每个物体最多持有 5 条观测（status held）。超员时宿主自动按点数和视角分散度保留最优的 5 条，多余的转为 discard。 模型可以在 hold 动作里加 evict 字段覆盖这个选择：写一个 id 字符串或 id 列表，指定想换出的持有观测；不写也不报错，宿主会自动选。 

{"action":"hold","object_id":"Object3",
 "observations":["0185:003"],
 "evict":"0042:001",  // 可选；检视发现此条持有是错的时才需要写
 "evidence":["0185:003","0042:001"],
 "reason":"0042:001 是错误归属，换掉"}

六种动作

动作含义1105-v1 变化
hold把观测归到已有物体改名自 assign；上限 5 条；超员由宿主自动淘汰（evict 可选）；verify 检查
discard丢弃观测（最终决定）改名自 defer；批量上限从 4 提高到 10
create新建物体（不含观测）verify 新增重叠检查
exclude排除观测（跨物体 mask）无变化
relabel修正物体标签无变化
merge合并两个物体verify 新增超员检查；超员须重新 propose 加 discard
兼容
旧名 assign / defer 在输入侧已被拒绝（Unknown action）。 旧 run 的 state.json（status assigned / defer）仍可读取——pagegen 和 spatial_context 对两套名称都兼容。

证据引用规则

每个动作必须有非空 evidence 列表和 reason。 本窗口观测 id 开窗时自动进入证据集，引用它们不证明做了任何检查。 历史 id 只有通过 inspect_object 或 inspect_observations 看过后才可引用； 引用未看过的历史 id，报错并按名指出。

06提交后 verify

src/harness/verify.py · propose_update 通过后自动触发

触发
对提案里每条 hold / create / merge 动作检查；discard / exclude / relabel 不检查
计数
max_verify_rounds = 2，独立计数，不占 max_calls；2 轮后强制允许 commit 并记日志
渲染
Python PIL + camera_to_world + intrinsic_color（均来自 scene_amb3r_v2）；2D 反投影，不做 3D 渲染

三种检查

动作检查内容触发条件
hold 有 camera_to_world 时，把目标物体的其余持有点云投进新观测所在帧；命中率（落在 mask 内的比例）< 20% 时渲染，每次最多 6 张（最差的排前面） 命中率 < HOLD_HIT_THRESHOLD（0.2）
create 计算新物体点云与每个已有物体的重叠率（10 cm 容差）；重叠 >10% 时渲染重叠最多的物体的反投影图 与已有物体重叠 >10%
merge 合并后持有数是否超过 5；超员时告知超员 N 条 合并后持有数 > HOLD_LIMIT

verify 流程

1
propose_update

2
verify.build_checks()

确认无误
模型调 commit_update → 落盘 → 窗口结束
3b
发现问题
模型重新调 propose_update（修改 object_id / 加 discard / 在 evict 里指定换出的观测）→ 回到步骤 2
4
2 轮未通过
强制允许 commit，记录到 verify/ 目录，继续下一窗口
反投影精度受 AMB3R 跨帧误差限制（中位 6.6 cm，p90 13.1 cm）。间距约 9 cm 的同一双鞋， 点云与 mask 可能看起来略有偏移。间距 0.4 m 以上（凳子、椅子）可以可靠区分。

07契约与失效

改哪一段，会让哪一段失效

改动影响范围需要重跑
更换 prompt.txt所有未来窗口；已提交窗口不受影响新的 run（旧 checkpoint 不兼容新 prompt hash）
更换 source（v1→v2）全部几何、camera_to_world、verify 反投影完整重跑；旧 run 继续指向旧 source
调整 HOLD_LIMIT已有 run 的 state.json 里可能有超限物体新 run；旧 state 按旧规则读（向后兼容）
调整 SAM 面积阈值感知输出变化，source 需重新生成重跑 gpt_sam31 + amb3r_mask_source + harness run
调整候选规则（gap/overlap 阈值）每窗口候选列表变化，影响归属决策新 run；不影响已有 source
