逐个处理带出的三个问题，以及方向（用户 2026-11-12，具体设计未定）

用户原话里做选择的一方叫"harness"，下面按我的理解写成 agent（在 harness 里借助工具做判断的模型）。

问题方向
批内的处理顺序怎么排。逐个渲染之后，排在后面的物体才能看到前面的；被支撑的物体排在支撑物前面时，渲染出来是悬空的。 批内顺序由 agent 自己选。这是它拿到一个批的输入之后要做的第一件事。
处理后面的物体时，发现前面的物体有问题。例如放床头柜时才发现床太宽。 加一个"扩展批次"的工具。把之前那个物体的信息拿进当前批次，在当前批次里修。
已处理好的物体换一个关键帧看可能不对。床是在关键帧 45 下处理的，第 2 步在关键帧 55 下看到的是它的另一个角度。 批内的关键帧是共享的。物体一个一个处理，但这一批的关键帧对批内每个物体都可用。
允许 agent 要求换视角渲染：处理某个物体时，可以要求在批内其他关键帧的视角下渲染。

具体设计时要回答的问题（我列的，未讨论）

  • 排顺序之前 agent 能看到什么。它要先知道批里有哪些物体、各自大概在哪，才排得出顺序。是否在开头把这一批的关键帧照片和物体清单一起给它。
  • 顺序定了之后能不能改。处理到一半发现顺序不对时怎么办。
  • "扩展批次"拿进来的是什么。资产、已提交的位姿、文字卡是必需的；那个物体自己的首个关键帧要不要一起加入当前批的共享关键帧。
  • 改了之前的物体之后，谁要重看。它原来所在批里和它相邻、或放在它上面的物体，位置是相对它定的。
  • 扩展有没有上限。一个批最多拿进来几个，避免一批越滚越大。
  • 换视角渲染的范围。只限当前批的 4–5 张首个关键帧，还是也包括扩展进来的物体的关键帧。
  • 换视角时轮廓 IoU 怎么算。关键帧归属只记录了"这一帧是谁的关键帧"；在别的物体的关键帧下，当前物体没有对应的 mask（见 D02 的关键帧数据）。

两个预览共同的、需要定的事

  • 渲染里没有房间。只有一块灰色地面，没有墙，背景是 Isaac 的网格。照片里的墙、地毯、海报在右边都没有对应物。
  • 不在物体清单里的东西不会出现。例如照片里的办公椅，52 个物体里没有它。
  • IoU 是离线渲染器算的，不是从 Isaac 的图算的。两者用同一套相机和位姿（之前核对过逐像素一致），但要从 Isaac 直接出数，需要它另外输出实例分割。

拦截的三条规则（用户 2026-11-12 确认）

  1. "拦截"和"自动撤回"是同一件事。改动立即生效 → 自动验证 → 不过就撤回这次改动，并把原因告诉 agent。
  2. 判据是"不允许比改动前更差"，不是要求一步到位。初始位姿本身常常带着问题（预览里床头柜一开始就陷在床里），只要这次改动没有让它变得更差，就不撤回。
  3. 连续被撤回有上限。到了上限，这个物体标记为失败，不再循环。
