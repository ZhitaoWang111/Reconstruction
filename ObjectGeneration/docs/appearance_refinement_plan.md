# GPT-6 + Blender 外观精修开发方案

日期：2026-10-12。状态：设计完成，待开发和实测。本文中的新增文件、参数和命令均为计划接口，不代表当前已经可用。

## 1. 目标与首版边界

目标：在保留 SAM3D 几何结构、现实尺寸和物理配置的前提下，使用原始照片改善包装图案、标签、颜色及材质表现，交付可迁移、可在 Isaac Sim 使用的资产。

首版优先支持不透明瓶、罐和盒装商品。先完成一个物体的端到端实验，再扩展到现有 12 个物体。对袋装商品按实验结果决定支持等级。

首版必须具备：

- 读取已有运行目录，不重新执行 SAM3D。
- 原照片与模型的相机对齐，支持人工提供对应点修正。
- 保留现有顶点颜色作为未观测区域的回退来源。
- UV、照片投射、基础色贴图和分区域粗糙度/金属度。
- GPT-6 查看对比图，调用受控 Blender 工具完成有限轮次优化。
- 保存可编辑 Blender 工程和带外部贴图的标准 USD。
- 人工选择接受、重试或保留原版；失败不影响原版资产。
- Isaac Sim 显示、物理及资产迁移验证。

后续扩展：多视角照片融合、透明塑料与玻璃、精细法线、自动批量接受。单图背面包装不作为真实恢复承诺；图像生成补全独立标注，默认关闭。几何重建、减面和重拓扑不进入本期。

## 3. 总体架构与技术决策

```text
现有运行目录：RGB + mask + mesh.glb
                    ↓
4_convert：标准化规范网格 / usd/object.usda
                    ↓
4_appearance：编排器
    ├── GPT-6：分析照片、材质计划、渲染比较、下一步操作
    ├── MCP 客户端 → Blender 插件：场景操作和观察
    ├── 固定算法：对齐、UV、投射、烘焙、评估
    └── USD 写入器：回写原规范网格的 UV 和材质
                    ↓
人工确认 → 选择精修版本或原版
                    ↓
5_physics → 6_visual + 6_drop → 可选组合场景验证
```

决策：

1. 放在阶段 4 与 5 之间，避免同时处理 GLB 和 USD 两套坐标、缩放规则。
2. 原规范 USD 为几何权威来源。Blender 是外观工作区，不直接用其通用 USD 导出替换物理脚本依赖的层级。
3. 主路径不修改顶点位置、拓扑和 root/Mesh 路径。UV 使用面角数据，材质分区使用 GeomSubset，维持单 Mesh。
4. 若 Blender 导入导致三角顺序或顶点索引变化，必须保留显式对应映射；映射不唯一或不可验证则停止。不得用近邻匹配静默掩盖错误。
5. 对齐优先移动相机。禁止通过拉伸网格拟合照片轮廓。
6. GPT-6 选择受控操作与参数，固定代码负责大量数值计算。首版不向模型开放任意 shell；底层执行代码由本地模板生成。
7. 首版使用标准 UsdPreviewSurface；复杂 Blender 节点先烘焙。透明材质另设研究任务，须在 Isaac RTX 验证。
8. 阶段按顺序释放 GPU：SAM3D 退出后启动 Blender，Blender 保存并退出后启动 Isaac Sim。

`fit_camera` 等确定性任务由工具直接执行或提交任务；GPT-6 不在对话中处理完整顶点数组。工具返回摘要、产物 ID、图片和错误码。API 侧传图片字节或可访问 URL，不能把本地路径当成模型可读取的图片。

长任务返回 `job_id`，查询接口返回 queued/running/success/failed、进度和产物；进程退出码、MCP 返回文本和产物报告联合判断成功。不能把包含错误的字符串或 socket 超时当作任务完成。

## 5. 外观算法路线

### 5.1 基线和相机拟合

读取原始输入 manifest，解析实际 mask 路径，不假设 mask 一定位于 input。保存原图裁剪、mask、规范几何指纹及前/后/侧/俯视基线。

相机拟合优化旋转、距离、焦距/视场角及取景位置，保持网格不变。使用 mask IoU、轮廓距离与对应点误差联合评价。处理裁剪、图像坐标和相机参数的转换并记录矩阵。

对称瓶体存在朝向歧义，应结合标签区域和人工对应点；对齐不通过时进入 `needs_alignment`，不能继续把错误投射交给模型调整材质。

### 5.2 UV 与照片投射

- 瓶/罐：瓶身圆柱展开，盖和底分别展开；接缝尽量放到照片不可见侧。
- 盒：按平面分区展开，避免跨面拉伸。
- 袋：通用展开，提供拉伸可视化，严重区域允许人工修正。
- 在 UV 空间烘焙原顶点颜色作为基底，再叠加高置信照片内容。
- 使用深度可见性、mask 内缩及表面朝向权重，排除背景、遮挡和掠射角区域。
- 设置 UV gutter 和边缘扩张，生成 mipmap 时避免接缝漏色。
- 输出照片覆盖图和未观测区域标记。背面不得无记录镜像正面品牌文字。
- 首版默认 2K，允许 1K/4K。照片本身模糊时增加分辨率不能恢复真实细节。

### 5.3 材质与光照

GPT-6 输出区域类别、建议参数和不确定性；区域分配由投影关系、颜色及人工修正完成，不能只依赖模型返回一个文字描述。

基础色使用 sRGB，粗糙度/金属度等数据贴图使用线性解释。首版支持基础色、粗糙度、金属度；无可靠依据时不添加法线细节。

同时输出基础色诊断渲染与统一光照的美观渲染，分开检查图案和材质。保守处理照片高光、阴影，避免强行去光照破坏印刷图案。

### 5.4 有限迭代

默认最多 3 轮、单轮受控操作数上限可配。每轮保存候选、对比图、数值指标和模型理由。优先处理相机、贴图映射，再处理材质参数。

连续两轮无改善、预算耗尽或重复工具错误则停止；保留最佳候选并进入人工确认，不自动声称优化成功。预算/时间/轮数上限彼此独立，任何一个达到都停止新请求。

## 6. 状态、版本与目录契约

保留四个顶层目录：

```text
output/<RGB 名>/<启动时间戳>/
├── input/                         # 原始输入与原流水线报告
├── sam3d/                         # 原始 GLB 和 Splat
├── usd/
│   ├── object.usda                # 阶段 4 基线，不覆盖
│   ├── object.conversion.json
│   └── appearance/
│       ├── selection.json         # 明确记录原版或 revision ID
│       └── <revision>/
│           ├── config.json
│           ├── manifest.json
│           ├── report.json
│           ├── work.blend
│           ├── object.usda
│           ├── textures/
│           ├── renders/
│           ├── camera.json
│           ├── review.json
│           ├── tool_calls.jsonl
│           └── iterations/
└── physics/
    ├── object.usda                # 已有基线仍保留
    └── appearance/<revision>/     # 精修物理资产及全部验证报告
        ├── object.usda
        ├── textures/
        └── ...
```

revision 使用唯一时间戳或明确递增 ID，创建时加锁；相同运行目录不并发修改同一 Blender 工程。manifest 记录源文件 SHA256、几何指纹、版本、模型 ID、参数、依赖和阶段报告。

状态：`pending → preflight → baseline → alignment → texturing → evaluation → awaiting_review → approved → usd_verified → physics_verified → success`。分支状态包含 `needs_alignment`、`rejected`、`failed`、`cancelled`、`budget_exhausted`。

人工操作为接受候选、重新调整、保留原版。等待确认属于 `awaiting_review`，必须与卡死区分；日志显示本地页面地址和恢复方式。关闭页面或中断不能自动接受。拒绝候选后可明确选择原版继续，报告记录 `fallback_original`。

重试只新建候选或恢复未完成阶段，不覆盖成功版本。输入、配置或工具版本指纹变化时，相应阶段失效；确认后的候选发生变化必须重新确认。

原流水线成功记录不被精修覆盖。独立精修报告不能继承旧的 Isaac 验证结论，新候选须产生绑定本次资产和依赖指纹的新验证证据。

## 7. API 与 Blender 运行配置

初始候选模型 `openai/gpt-6-astra`，公司网关 `https://vibeg.seer-robotics.cn/openai/v1`；启动探针确认当前可用性，不自动换成其他模型。凭据从现有 API 配置或环境加载，日志和产物只记录模型及脱敏请求摘要。

优先实现一个协议适配器。由最小探针决定 Responses 或 Chat Completions 的首版协议，记录选择原因。需要验证图片输入、工具参数、结果回传、模型后续看图反馈完整往返。

Blender 使用 `/home/seer/wzt/Blender/.local/opt/blender/blender`。使用仓库内固定 MCP 版本，记录 Git commit；首版采用独立 Blender 会话，避免编辑用户当前工程。交互会话通过 MCP 控制，重烘焙可使用单独 batch worker；不要假定 viewport 工具可直接运行于 headless 环境。

限流/短暂网络错误可有限退避重试；鉴权、余额、schema 和模型不支持错误直接停止。对超时工具先检查 job 状态，禁止盲目重复执行有副作用的操作。

## 8. CLI 与流水线接入（原计划；M5 当前入口见 README 第 8 节）

独立精修已生成物体：

```bash
./scripts/refine_appearance.sh \
  --run-dir "$RUN_DIR" \
  --config configs/appearance/default.yaml
```

- `--run-dir`：已有四目录运行路径；不执行 SAM3D。
- `--config`：模型、Blender、贴图尺寸、任务超时、API 预算和人工确认策略。
- 默认保持物理质量等现有参数；读取已验证配置并核对 USD，来源缺失或不一致时要求显式设置，禁止回落到 1 kg。

新资产的端到端命令追加计划选项：

```bash
./scripts/run_pipeline.sh \
  --image assets/Beverages_And_snacks/5.jpg \
  --prompt 'white bottle' \
  --low-vram --sequential-condition \
  --height 0.14 --mass 0.5 \
  --prim-name Bottle5 --asset-name Bottle5 \
  --collision-approximation convexHull \
  --output output --seed 42 \
  --appearance-config configs/appearance/default.yaml
```

- 不提供 `--appearance-config` 时保持现有阶段 3、4、5、6 行为。
- 按用户最新要求，页面仅展示，无人工修正/确认门槛。当前先执行原 3→4→5→6，再执行 `7_appearance`；从原物理资产复制物理属性，技术验证通过后记录最终精修包路径。
- 新资产的 RUN_DIR 仍由阶段 3 自动分配，不需要人工赋值。
- 阶段 5 的输出、阶段 6 的输入和报告目录必须共同由选中 revision 推导。

计划增加独立恢复入口，接受 run-dir、revision 和 resume；按报告和产物指纹判断恢复点，不通过“文件存在”推断成功。

## 9. 里程碑与开发顺序

| 里程碑 | 任务及依赖 | 交付物 | 退出条件 |
|---|---|---|---|
| M0 能力验证 | API 图片+工具往返；Blender 导入、观察、保存、渲染；固定版本 | preflight 和能力报告 | 一轮真实 GPT-6→工具→渲染→反馈成功；不改已有资产 |
| M1 契约与基线 | 依赖 M0；manifest、几何指纹、状态、基线、输入解析 | contracts、baseline、数据样例 | 现有资产读取正确，原始数据不变，任务能中断恢复 |
| M2 贴图闭环 | 依赖 M1；先人工相机/对应点，完成 UV、投射和贴图 USD | 一件不透明商品的精修 USD | 标签可辨性和图案位置改善，规范几何不变 |
| M3 自动对齐和反馈 | 依赖 M2；轮廓优化、GPT 工具循环、人工确认 | 相机拟合、迭代记录、对比页面 | 对齐失败可修正；预算、回退、确认流程可靠 |
| M4 最终资产交付 | 可在 M2 后推进；贴图打包、物理和 Isaac 显示验证 | 独立物理资产包及验证报告 | 移到新目录并隐藏原路径后仍可加载；显示与物理均通过 |
| M5 流水线接入 | 依赖 M3/M4；参数、路径、恢复、场景版本选择 | 独立及端到端入口、README | 旧命令兼容；新命令与已有 run-dir 精修都通过 |
| M6 多物体验收 | 依赖 M5；瓶、盒、袋代表样本，逐步覆盖 12 个物体 | 每物体对比报告和新组合场景 | 无静默降级、无旧报告误用；人工逐件确认 |

先完成单物体 M0→M1→M2→M4，尽早证明贴图可以真正到达 Isaac Sim；再增加自动决策和批量能力。初期人工相机设置是可记录的启动手段，不冒充自动对齐完成。

每个里程碑以独立代码变更和验收记录交付，不一次性改动整条流水线。时间与 API 消耗在 M0/M2 实测后估算，当前不预先承诺自动成功率或固定完成时长。

## 10. 验证矩阵与质量门槛

| 验证层 | 内容 | 通过要求 |
|---|---|---|
| 数据契约 | schema、错误状态、选择版本、输入变化、恢复 | 不误选版本，不重用失效产物 |
| 几何保持 | points、面索引、尺寸、root/Mesh、xform | USD 写入以原始几何数组为源；任何非预期改变拒绝提交 |
| UV/材质 | 面角数量、UV 有限值、材质分区、纹理通道和颜色空间 | 无缺失依赖、非法值及未覆盖面；有接缝检查图 |
| 相机对齐 | mask IoU、轮廓距离、关键点、标签朝向 | M2 建立阈值；IoU 0.90 可作初始目标，不作为所有物体通用保证 |
| 图案保真 | 标签位置、原图可读文字、颜色、拉伸 | 原图可读信息不因优化变错；人工接受；无依据背面明确标注 |
| 闭环工具 | API 和 MCP 错误、超时、长任务、中断、预算 | 重试不重复副作用，失败原因可定位，原版可继续使用 |
| Isaac 显示 | 原视角及多角度、UV 棋盘格/颜色测试资产 | 贴图确实被渲染采样；仅存在材质绑定不算通过 |
| 物理回归 | 质量、质心、惯量、碰撞、摩擦及掉落 | 与基线在已有浮点容差内一致，新的掉落检查 passed=true |
| 资产迁移 | 依赖递归复制、相对路径、重定位 | 包移动后独立打开；验证时原始目录不可用于解析依赖 |
| 场景集成 | 新 revision 的选择、12 个物体组合与仿真 | manifest 绑定精修资产指纹；显示和场景检查均通过 |

图像相似度只在固定相机、裁剪和评价条件下比较，不能通过改变灯光掩盖标签错误。先用三类代表样本校准阈值，再制定批量门槛。

若物理属性重新计算，惯量应优先比较重构后的惯量张量；主轴四元数符号或等价特征向量方向变化不应被误判为物理改变。

新增测试重点为坐标投射、UV 面角映射、依赖重定位和状态恢复；MCP/API 使用可控模拟测试错误分支，真实调用只用于能力探针和集成验收。不要用反复启动大型模型替代这些小型测试。

## 11. 完成定义

首版完成需同时满足：一个已有物体可独立精修；一个新物体可端到端生成并确认外观；原几何和物理参数保持；精修贴图在 Isaac Sim 正确显示；独立资产包可迁移；中断后能恢复；旧命令行为兼容；README 有可执行命令、参数解释、报告位置及失败处理方式。

“插件能连接”“Blender 效果更好”“API 返回 200”均只属于组件证据，不等于外观精修流水线完成。
