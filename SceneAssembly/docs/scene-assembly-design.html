场景组装 harness 设计框架

agent 看照片做判断，用工具改位姿；harness 把每次改动精确执行，马上检查，变差就撤回，做不到就打回并说明原因。 SAM3D、扫描点云和配准只用来定起点和做检查，不替 agent 定位置。

00总览

整场景五步 · 只有批会话调模型 · 每批一个新对话

01
准备（本地）
输入 资产交接 + 场景交接 + 墙体交接  →  输出 52 个物体的起点（M3）、11 个批次（M6）、常驻 Isaac 服务（M1）
02
批会话 × 11（agent + harness）
输入 开局材料 + 之前批的状态  →  输出 本批每个物体 done 或 failed，一个断点版本号
03
全局物理（本地）
整场景 15 s 重力仿真；倒下或掉落的物体标为失败，不撤回（这时已经没有 agent 能接手）
04
导出
scene.usda：引用 structure.usdc，每个物体引用自己的 physics.usdc 并带 4×4 矩阵和状态；带关键帧相机和物理场景
05
评估（agent 看不到）
留出帧轮廓 IoU、三个基线、最终几何与物理、过程指标 → eval.json + report.html

一个批会话内部：Observe → Reason → Act → Verify

Observe · 开局一次给齐（M5）
文字卡 · 已放物体清单 · 墙段表 · 平面图 · 带框关键帧 · 四面图
不靠 agent 逐个调工具去要；之后每次改动自动返回一张拼接图
Reason · agent（M7）
set_order → begin → 对照拼接图 → 决定位姿和支撑
朝向、朝上轴、三轴缩放、放在什么上、贴哪面墙，都由 agent 看图决定
Act · set_pose 立即生效（M2）
位姿 + 支撑 → 4×4：落 z、贴墙，或打回
放在它上面的物体跟着走；支撑面或墙对不上就打回，状态不变，说明原因
Verify · 自动检查（M4 + M1）
改动前后各测一次 → 硬性项变差就自动撤回
返回结论、问题列表、被带动的物体和拼接图；被撤回的那张图标 REFUSED。连续 3 次撤回 → 物体失败
还不满意
再 set_pose / undo / view / check_scene
满意 · finish
5 s 重力仿真，倒下或掉落就撤回上一次改动
批末 · end_batch（M6）
绝对阈值 + 15 s 物理；有问题的物体重开一次，第二次仍不过标为失败
通过后写断点版本号，下一批从这里开始
agent
只做判断：处理顺序、朝向、朝上轴、三轴缩放、支撑、贴墙、何时完成、何时放弃、要不要把别批的物体拉进来。
harness
执行和记账：落 z、贴墙、带动上面的物体、渲染、测量、撤回、物理仿真、版本快照。它不猜：支撑面或墙对不上就打回。
和测试实验
2026-11-11 的测试实验（批 1，r2，legacy 代码）有 5 个候选、提议后再提交、警告只要求解释、离线渲染且没有墙，已全部替换，见 debug 记录 D01–D06。旧版页面在 archive/。

01设计原则

每条都对应一次讨论定下的事 · 编号指向 debug 记录

原则具体做法出处
agent 判断，几何作证据朝向、支撑、缩放、贴墙由 agent 看图决定。SAM3D 和一次有界配准只给起点，起点的朝向明说未经确认D03
点云不用来贴合没有 fit_to_scan。点云只作为验证指标，而且排在最后D06-4
改动立即生效，自动验证没有"提议 / 提交"两段式；每次改动都检查，硬性项变差就撤回D01 · D06-1/2

验证优先级物理没错（穿插、穿墙、出房间）> 依赖关系对（支撑成立、贴墙贴着）> 看起来像照片 > 和点云重叠D07-0

让模型从图上取信息不给 agent 轮廓 IoU 这类加工过的数D08

03输入

M0 · 三份交接 · 全部在 scannet_scan 坐标系

交接位置用到的内容
资产交接 assembly_handoff/v2ObjectGeneration/output/scene0000_00/gt/assembly_handoff/52 个 USD 资产（视觉网格；physics.usdc 里的碰撞体、质量、摩擦）、SAM3D 旋转、资产尺寸
场景交接（实例识别）由资产交接的 manifest 指向，校验哈希相机内参、每个物体的扫描点云、1–3 张关键帧（RGB + mask + camera_to_world）、floor_z 0.0544
墙体交接 structure_handoff/v2ObjectGeneration/output/scene0000_00/structuregen/structure_handoff_scannet_scan/structure.usdc：9 段墙（6 外 3 内）、3 块地板、饰线。structure.json：墙段线、朝房间的法向、厚度、洞口（只有 int_1 一个），地板多边形。地板顶面 0.054，层高 2.55 m
只给评估场景交接指向的原始数据ScanNet 2D 实例标注、传感器深度。agent 看不到
坐标系
gt/ 交接的资产一律在 scannet_scan 下组装，墙体交接也是这个坐标系，不做变换。两份交接的地面差 0.4 mm（0.054 / 0.0544），按 1 cm 容差校验。
没有的东西
天花板、门扇、窗、窗套都没有；"固定在天花板"这一类先不做。门窗允许和墙相交（按标签 door / window 豁免）。
资产实况
37 个可动、12 个固定（柜子、台面、吊柜、淋浴间等）、3 个只按指定运动（窗帘、门）。碰撞体 35 个是单个凸包，17 个是凸分解。床和柜子 0008 的凸包会把床面凹处和柜格填实，暂时保留，跑完数据再定（D06）。

04起点

M3 · src/initial/ · 每个物体只给一个起点，不给候选

1
朝向
SAM3D 旋转换到场景 → 取最近的朝上轴和 yaw；剩下的倾斜置 0（中位 6.3°，多为误差）
2
倒置翻正
朝上轴为 −Z 的 6 个改成 +Z、yaw 不变，文字卡标"朝向未确认"：窗帘 0006、冰箱、洗衣篮、微波炉、obj_0061、镜子。生成的资产都是正立的，−Z 只能是 SAM3D 转倒了
3
位置
扫描包围盒中心，再做一次有界配准：yaw ±20°、位移不超过 0.25 m（欧氏距离）、高度不动；变差就保留起点
4
高度
扫描点底面（2% 分位，低于地面按地面），不声明支撑（内部的 height 类型，agent 不能用）
5
缩放
三轴都是 1

52 个一次算完，缓存在 <run>/init/initial_poses.json，交接 manifest 变了就重算。

起点不是答案。 顶点到扫描点的中位残差 25.8 cm（缩放为 1 时资产占地普遍偏大）；起点底部离地中位 6.1 cm（多数是放在别的东西上、还没声明支撑的物体）；床起点穿墙 0.248 m、出房间 0.26 m。 用从不移动物体的脚本化模型跑完全局物理：52 个里 15 个倒下或掉落，多数是起点就互相穿插被弹开。 所以 agent 第一次改动一个物体时必须声明支撑，批末检查也会逼它处理起点带来的穿墙和出房间。

05位姿与支撑

M2 · src/state/ · agent 不给 z

pose    = (x, y, yaw_deg, up, scale[3], tilt_deg, tilt_toward_deg)   + support
up      资产自己的哪根轴朝天：±X ±Y ±Z，默认 +Z
scale   摆正之后资产自己的长、宽、高，三个系数各自独立
yaw_deg 绕 +Z 逆时针，从 +X 起算
tilt    倒多少度、往哪个水平方向倒；默认 0，倾斜放置的物体才用
(x, y)  摆正、缩放后的包围盒中心，转动绕它进行
z       不给：由支撑决定
顺序    朝上轴 → 三轴缩放 → yaw → 倾斜 → 平移；倾斜后仍由最低点落到支撑面
支撑agent 给z 怎么来打回的情况
floor—地板顶面 0.054—
objecton；多层家具可给大致的 surface_z在支撑物的视觉网格上找朝上的面（法向 z > 0.3）：从 surface_z 上方 0.15 m 往下找 0.30 m；不给 surface_z 时从当前底面上方 0.05 m 起找范围内没有面；支撑物不在场；成环（床放到枕头上）
wallheight：底面离地高度地板 + height超过层高；挡住门洞
against（附加，可配 floor / wall）["auto"]，或 1–2 个墙段名不影响 z。只沿墙法向推到刚好贴住（间隙 0），沿墙位置不动；反馈里写明贴到哪面、推了多远auto：最近的墙超过 0.30 m，或第二近只差不到 0.15 m（墙角，要求指明）；两段墙夹角不在 75–105°；挡住洞口
heightagent 不可用起点专用：扫描底面—
带动
支撑物改动后，放在它上面的物体（递归）保持相对位置跟着走，重新落 z，和这次改动算同一个版本；整个改动要么全成功要么全不变。反馈里列出所有被带动、位置变了的物体（注明 "rests on …"）。
撤回
undo 撤单个物体的上一次改动。上面的物体跟着回去，它们自己后来的改动保留；如果撤回的物体的支撑物后来动过，按它在支撑物上的相对位置还原。
状态
untouched（不渲染、不参与碰撞）→ working → done / failed。失败的物体留在场景里，用最后一个没被撤回的位姿，参与渲染和检查，导出时标出。已完成的再改会回到 working。每个版本一份完整快照 states/vNNNN.json，外加 actions.jsonl。
已知代价
"放在物体上"按支撑物的视觉网格落 z。资产床面比真实床面低时，小物体会跟着低：批 3 的 obj_0061 比扫描底面低 5 cm（D12）。

08工具与对话

M7 · src/agent/ · 10 个 strict 工具

工具作用返回
set_order定本批的处理顺序；begin 之前必须调顺序
begin开始处理一个物体，它按当前位姿进场位姿、支撑、底面高度 + 拼接图
set_pose改位姿和支撑，立即生效 → 检查 → 硬性项变差就自动撤回keep / undo、问题列表、moved（含被带动的物体、贴墙推了多远）、当前状态 + 拼接图；打回时只有原因
undo撤这个物体的上一次改动回到的版本、跟着回去的物体 + 拼接图
view换本批另一张共享帧看拼接图
check_scene列出全场景当前的问题，不改东西没声明支撑的接触、穿墙、出房间、支撑间隙、贴墙间隙
finish标完成；它和它上面的物体跑 5 s 重力每个物体的位移、倾角；倒下或掉落则撤回上一次改动、物体保持打开
give_up标失败（例如资产和照片对不上），留在场景里剩下的物体
bring_in把别批的物体拉进本批，最多 3 个文字卡、四面图，必要时一张帧
end_batch全部 done 或 failed 后结束本批，跑批末检查通过，或被重开的物体和原因
对话设置值
模型与接口七牛云/coding-openai/gpt-6-astra，OpenAI Responses API，密钥来自 Gateway/key.json（日志里隐去）
调用tool_choice auto、不并行、reasoning effort high，推理摘要写入日志；历史只追加不改写
上限每批 80 轮或 300 万输入 token；没调工具就提醒，连续 2 次后停；超限时剩下的物体按最后位姿标失败
计价每百万 token：输入 $10、缓存读 $1、输出 $50。批 3 的 31 轮里 21 轮命中缓存，缓存读占输入 token 的 57%

有 stop → 自动撤回
告诉 agent 原因，图标 REFUSED；同一物体连续 3 次自动撤回 → 标失败
检查怎么测报告撤回类别
穿插Isaac 接触报告：零重力走一步，只回答有没有接触，不给深度。与声明的支撑物之间的接触不算—新出现的接触对物理
穿墙视觉网格表面采样点进墙的最深距离> 0.01 m> 0.02 m物理
出房间占地超出地板多边形的距离> 0.02 m> 0.05 m物理
支撑悬空底部 5 cm 带到声明支撑面的间隙> 0.01 m> 0.05 m依赖
支撑陷入同上，负间隙> 0.01 m> 0.03 m依赖
支撑声明底面落在支撑物上的比例—< 0.20依赖
贴墙间隙声明 against 的物体到墙面> 0.01 m> 0.05 m依赖
缩放任一轴不在 0.5–2.0报告不撤回软
点云扫描点被覆盖的比例（5 cm 内）、资产超出扫描的比例；覆盖降或溢出升超过 0.05报告不撤回软
豁免
标签为 door / window 的物体不查穿墙和出房间。淋浴间、镜子、窗帘、钟照常检查，可以声明贴墙或挂墙。
为什么只要是 / 否
Isaac 的接触报告给的 separation 不是穿插深度；Drake / FCL 在生成网格（薄壳、不封闭）上做凸分解，量出的深度虚高 2–4 倍。先只用是否接触，以后有问题再升级（用户 11-20）。
返回的口径
set_pose 只报告变差了的问题。起点就有、这次没变差的问题不出现在返回里；要看全貌得调 check_scene。提示词写的是"已有且没变差的问题会报告并保留"，和代码不一致（批 3 吊柜的例子见复盘页）。
