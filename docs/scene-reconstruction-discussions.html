第十五轮 · 外表面约束 3D bbox2026-09-24当前实现 · 已重算前30帧的36个物体

用物体外表面的法线定朝向，用表面位置约束框面

本轮汇总当前实际生效的出框方法，更新第十三、十四轮的方向选择与参数。框始终保持世界 Z 轴竖直；表示已观测点云的近似范围，不补全不可见物体，也不修改原始实例点云。

15.1 · 为什么调整

之前的问题现在的处理
平面支持点的主轴只是朝向候选，加分后仍可能落选；没有直接约束框面的位置。可靠竖直外表面的水平法线直接确定朝向；符合条件的框面由表面支持点定位。
局部平面的水平 footprint 曾用于裁剪整个物体，导致衣柜连续侧面被排除。停用 footprint 裁剪。平面的可见宽高不作为整个物体的宽高。
稀疏但真实的部件可能被过强过滤移除。世界轴每端裁剪回调至 0.25%，密度阈值回调至中位数 + 4.5 MAD；仍保留连续尾部检查。

15.3 · 衣柜的一个侧面，具体起什么作用

  1. 表面证据找到衣柜侧面

    不是用整团点的最长方向猜长边，而是估计侧面法线。

  2. 方向约束框的侧面与其方向对齐

    保持 Z 竖直，对近竖直平面做水平法线投影。

  3. 位置约束表面支持点定位一侧框面

    预留噪声余量，并保留分位覆盖保护。

  4. 完整范围其余点决定另一侧与宽高

    只看到半块侧面，也不会拿这半块的宽高裁掉其他部件。

本次生成数据中，Object005（fabric wardrobe）有一个框面记录了 2,080 个平面支持点；框尺寸约为 0.888 × 0.548 × 1.555 米。这是拟合证据与输出尺寸，不是完整物体真值或准确性证明。

12.2 · 代表观测按什么顺序选择

  1. ① 候选来源该Object的历史观测

    通过已有归属记录找到候选，读取各条观测对应的原始 RGB 和 SAM3 原始 mask。

  2. ② 计算指标原图清晰度 + bbox面积

    完整原始 RGB 用来计算清晰度；每条原始 mask 单独计算 bbox。同帧候选共用原图清晰度。

  3. ③ 选择一条清晰候选中选大框

    优先在清晰的候选中选择 bbox 面积最大的一条；清晰度算法和阈值尚未确定。

  4. ④ 组装图像完整RGB上画框

    绘制所选观测的 bbox 和 Object 编号，连同文字信息发送给 Agent。

bbox 大小按面积比较，跨不同图像尺寸时按整图面积归一化。若没有候选达到清晰标准，可采用“先选相对最清晰者，再以 bbox 大小打破并列”的兜底建议；具体阈值、并列与兜底细节在实现前确定。

01 · 把新 mask 变成一条可追溯的观测

例如给“抽样第 11 帧的第 4 个 mask”编号 obs_f0011_m04。程序保存原图、轮廓、局部裁剪、类别，以及利用已有深度、内参和位姿反投影得到的有效三维点。此时先不决定它属于哪个物体。

默认提供本窗 RGB 与带编号的 mask 轮廓、所有新观测的清单、相关历史物体的代表图，以及上窗待定项。小物体补裁剪图。历史候选用来减少阅读量，模型仍能查询其他旧物体。

出口 C · 还说不清保留待定观测

只露出一小块白色边角，不能确定是新物体还是旧物体的另一面。留给后续窗口判断。

“没有匹配到旧物体”并不足以证明它是新物体。首窗通常会创建多个暂定物体；后来发现重复建档，可以合并并保留旧 ID 的指向关系。

这里的“证据足够”指什么？

例如：当前侧面图能看到水箱与底座的连接；历史正面图能对上同一位置和外观；反投影点及重投影结果支持这一判断。模型需要指出具体观测编号、视角或测量结果，也要说明有没有相反证据。不是只报一句“我很有信心”。距离近、类别相同、点云不重叠，都不能单独决定是否同一物体。

每窗设置可配置的调用次数、工具次数和超时预算。达到上限仍不能判断，就记录原因并待定；API 失败时保留检查点，在重试范围内重试，不能把失败当作“没有物体”。

04 · 模型先交“修改单”，程序再落实

修改单写清：当前状态版本、哪些观测要归入哪些物体、是否新建／合并／重新分配、引用了什么证据、为什么这样改。程序先展示修改前后会影响哪些物体，再检查 ID、引用、归属冲突和版本是否有效。

检查通过后，程序提交新版本，只重算受影响物体的点云。失败则把原因返回模型修订。提交必须针对已经检查过、且仍对应当前版本的修改单；同一提交重试不能重复创建物体。

程序校验操作能不能执行；模型承担语义判断。“引用存在、版本正确”不代表“两个 mask 确实是同一个物体”。所以必须保留证据、旧版本和纠错入口。

可比较结果

对比三个设置：现有几何基线；模型关联但冻结历史归属；模型可主动取证并回改历史。采用同一输入与评估范围，待定观测计入覆盖统计，不能只统计成功融合的部分。真值只用于评估，不给模型看。

这次实验的边界

01 · Harness 在这里是什么意思

让模型能够持续、可靠地完成任务的一套运行机制。

在我们的任务里，它负责保存场景状态、组织模型看到的证据、提供查询与计算工具、执行状态变更，并把新结果反馈给下一轮判断。模型承担语义与身份推理，程序承担数据管理、工具执行、几何计算和运行控制。

下面的八部分是针对本项目的职责划分，不是通用标准，也不意味着需要八个服务或八个模型。初版可以放在同一个本地程序中，只保留清晰的输入、输出与修改权限。

任务范围沿用前轮约定：尺度与相机位姿由开源方法提供；现有类别和 2D mask 作为观测输入；这里研究跨帧身份、整体／部件关系与已观测三维点的归属。未观测表面补全和完整资产生成属于后续重建模块。

02 · 八个组成部分，各自交付什么

职责边界：只有变更提交层能修改正式的身份与归属状态；其他模块通过接口读取或提出建议。
组成部分核心职责输入 → 输出与边界
① 观测接入与证据档案
保存“当时看到了什么”		登记 RGB、类别、mask、相机与点图，分配稳定观测 ID，检查坐标、时间和几何版本，保留原件。上游结果 → 可追溯的观测记录。原始预测即使有错也保留；修订另存版本。缺失几何明确标记，不能凭空补点。
② 持久物体记忆
保存“目前怎样理解场景”		维护物体 ID、观测归属、部件／组合关系、未决假设和变更历史；区分已提交版本与待处理建议。证据引用＋提交记录 → 当前场景状态。融合点云是可重算结果；原始观测和归属记录是修正依据。模型会话文本不能承担唯一存储。
③ 上下文组织与取证工具
让模型能看到相关证据		组织本批概览、完整观测清单和历史摘要；提供历史视图检索、局部裁剪、三维渲染、几何测量与候选范围扩展。当前批次＋状态快照／模型取证请求 → 带帧号、观测 ID、物体 ID 和版本的证据。工具结果注明截断或缺失；类别不作为唯一检索门槛。
④ 模型判断与更新提议
回答“这些观测意味着什么”		检查新观测、识别歧义，提出关联、新建、身份合并、观测重分配、关系调整；也可以取证或暂缓。证据＋工具结果 → 结构化建议、引用证据、简短理由与未决项。每条新观测均有处理状态；模型不直接改数据库，也不生成几何坐标。
⑤ 运行调度与预算控制
管理“下一步做什么”		启动窗口、驱动模型与工具循环、分包、控制调用预算和超时重试，保存进度并恢复中断任务。待处理清单 → 可恢复的执行过程。预算用尽时保留未决项，不强迫模型做肯定判断；API 超时不等于“没有发现问题”。
⑥ 变更校验与版本提交
把建议变成可撤销状态		校验引用、操作权限、关系约束和基础版本；原子提交相关修改，保存理由和影响范围，防止重试重复执行。建议＋基础版本 → 新版本或明确拒绝原因。旧建议不能直接覆盖新状态；撤回产生可追溯的新修订，不删除历史。
⑦ 几何融合与结果派生
计算“每个物体有哪些点”		按已提交归属筛选有效点、融合体素、统计支持帧和空间范围，更新物体表面及可视化缓存。观测证据＋归属版本 → 带版本的物体点云。修改归属后局部重算；一个观测内部若混入其他物体，需另有点级筛选／mask 修订操作，改 ID 无法自动修好边界。
⑧ 运行记录、评估与检查页面
回答“发生了什么、是否变好”		记录证据、工具调用、模型建议、提交结果、失败及成本；展示逐批变化，支持人工核查和离线回放。运行轨迹＋结果快照 → 可解释的对照结果。GT 仅供独立评估，不能进入模型输入、候选筛选或提交判定。

①保存证据，②保存判断，⑦计算结果：这三个职责分开后，后续发现错误才能从原始观测重新组织点云。③负责提供信息，④负责解释信息，⑥负责落实修改：模型输出与正式状态之间有明确的执行边界。

03 · 运行架构：状态在外部，模型在循环中

04 · 用马桶水箱与底座，走完一次循环

以下是说明接口的假设例子，不是新增实验结果；A、B 是示意物体编号。

  1. 接入：某批新帧中出现水箱 mask 和底座 mask；档案登记观测 ID、源帧及反投影点，当前记忆中两者暂属于 A、B。
  2. 组织与判断：模型查看概览、局部图和已有记录，提出“A、B 可能是同一马桶的不同可见区域”，但当前遮挡使连接关系不清楚。
  3. 取证：模型请求同时看见 A、B 的历史视角；程序在已处理帧中检索，并提供轮廓标记图与空间测量。如果没有合适视角，返回缺失，保留未决直到新观测到来。
  4. 提议：若任务身份粒度与图像证据支持统一完整物体，模型提交 merge_identity(A, B)，附基础版本、观测引用和理由。若需要保留部件身份，则提议 part_of 关系；两类操作必须区分。
  5. 提交：程序核对 A、B 和证据是否存在、版本是否仍有效、关系是否冲突，然后记录一个新版本，保留原 ID 的解析关系及历史。发生冲突则返回原因，请模型基于最新状态修订。
  6. 融合与检查：程序重算受影响物体的表面点云。页面展示修改前后、涉及观测和证据；后续发现误合并时，通过新的归属修订重新计算。
“同一物体”“部件属于整体”“一组成对物体”需要不同操作。

两只鞋可以保留两个物理身份并建立一双的组合关系。若上游 mask 已覆盖一双鞋，应如实保存这一观测粒度，不能在没有新分割证据的情况下声称恢复了两个独立成员。整体／部件操作同样需要明确当前身份粒度。

05 · 合理性的关键：能发现、能取证、能修改、能纠错

  • 检查覆盖由程序保证。所有新观测进入清单，最终标记为已关联、新建、待定或明确排除；分包和预算限制不能造成静默遗漏。几何与类别可以帮助排序候选，模型仍可扩大搜索和提出未预设的问题。
  • 操作集合足以表达修正。支持关联、新建、合并身份、重分配历史观测、调整部件／组合关系、请求证据与暂缓。拆开误合并需要给出具体观测分配；仅输出“拆开 A”不足以执行。
  • 区分数据约束与判断证据。不存在的 ID、过期版本、循环部件关系、重复提交等必须处理；重叠低、类别不同等作为证据和复核线索。语义结论不能被简单几何阈值自动替代，也不能因格式合法就视为正确。
  • 提交结果可解释、可恢复。操作携带唯一编号、基础状态版本和证据引用；相关归属修改一起提交。保留操作日志与重算任务，使 API 重试和进程中断不会重复修改或丢失状态。
  • 未决是正常结果。每窗口限制取证轮次与预算；证据不足时等待新视角。模型的自报置信度只作辅助信息，不能当作已校准的正确率。
  • 判断与评估隔离。GT 只衡量结果；若沿用全视频 GT 修正的 AMB3R 几何，应注明这是固定几何条件下的增量关联实验，不能声称整个系统实现了严格在线重建。

01 · 为什么调整之前的方案

此前讨论过“本地发现歧义 → API 复核”，以及“定期让 API 主动巡检”。用户指出，人工规则难以覆盖所有问题：某次错误归属可能几何上看似合理，检查器没有报警，模型就永远看不到。此次将模型的职责进一步扩展为结合当前证据，提出局部物体状态的更新。

02 · 框架：每批新观测推动一次状态更新

场景尺度与相机位姿的研究边界沿用第四轮：交给开源方法。本轮关注的是哪些已观测点属于哪个物体。得到的是逐步积累的可见表面，不自动补全隐藏体积；完整资产重建仍属于后续模块。

03 · 物体记忆：原始证据、可修正关系、派生点云

每个物体至少保留持久 ID、类别及其变化、所属观测、代表视角、关系、未决问题与版本号。证据状态采用“暂定／有支持／有争议”等标记；模型自报的置信度不直接当作校准概率。

明确区分同一物体的不同观测、部件属于整体与多个物体组成语义组。柜门与柜体可以保留父子关系；鞋的一双保留成员关系。查询整体表面时可取其成员观测的并集并去重，不能把父子或组合关系等同于物体身份相同。

04 · 输入：以多帧为主，每个新观测都有处理状态

初版建议值：每 5 个新抽样帧组成一个窗口，前 30 帧共 6 个窗口。窗口内所有新 mask 都进入待处理清单，并提供每帧概览；根据画面密度按局部区域分包，再补充相关物体的 2–3 张历史代表视角。这些数值用于首轮对照，尚未验证最优性。一个窗口可能需要多次请求，不把“6 个窗口”写成“只需 6 次调用”。

输入内容用途与选择方式
当前窗口的 RGB 与轮廓图原图保留外观；轮廓图标出帧号、mask ID 与候选物体 ID。人工颜色仅是提示。小物体提供足够分辨率的局部裁剪。

  2. 修补 GPT 到 SAM 的目标约束。在少量困难样例中比较更具体的短语与带位置的候选范围，必要时在已定位区域使用视觉提示重新分割。范围须由图像或几何证据验证，不能把 GPT 猜测的框当真值；“whole cabinet”是否有效也要实测，不能只改名称就宣称问题解决。
  3. 同帧与跨帧一起判断归属。先找双向重叠、单向包含、相邻局部等候选，再检查它们反投影后是否得到其他视角的共同物体观测支持。111 的整体柜 mask 可以作为核对 112 局部 mask 的候选证据，尚需实际投影和遮挡检查。类别不同不直接排除同一整体，类别相同也不直接合并。
  4. 保留可交互结构。形成 cabinet 的整体展示时，仍保存门板 mask、部件候选和来源帧。后续再估计门的运动轴、可动性与碰撞几何。单帧门缝或相邻点云不够证明关节；对 SimReady 而言，永久压平部件会丢失后续交互建模需要的信息。
建议的数据关系（尚未实现）：observation_id → object_id，以及可选的 part_of、same_object、semantic_group 关系；每条关系保留证据与未决状态。原始类别、mask、帧号不改写。对象的可见覆盖可由多个已确认成员聚合，但不能由这个并集凭空补出被遮挡几何。

多视角共同包含可参考 MaskClustering 的视角共识思路。本项目的部件层级、按需修复与交互资产组织是拟议扩展，并非该方法已经保证的能力。一次误包的大 mask 不能直接成为合并依据；共同可见表面不足或几何误差较大时，应保持未决。

控制开销：对疑难对象复核，不给每帧追加一次 GPT

拟先利用已保存的 mask、包围范围与点云做候选筛选：同类粒度跨视角变化、局部与整体明显包含、不同类别占据相同表面等现象用于触发复核。这些检查也有计算成本，应限制候选邻域与关键视角，不做所有 mask 的全量两两比较。

只有归属冲突或边界缺失的对象，再选少量清晰且视角不同的 RGB＋编号 mask 裁剪交给 GPT 判断关系，或在候选区域重跑 SAM；结果按对象及证据版本缓存，新证据冲突时再更新。类别数与 mask 数不同本身不是触发条件，因为同类的多个独立物体是正常情况。

我们从一个具体的问题出发，你可以看一下tmp/下的3张图，房间中的同一个马桶在相邻3次识别中被打上了不同的语义标签，对于这种情况，我们如何使用点云和2D Mask，在下一步处理的时候能正确定位物体的类别标签和对应的占据点云？

先看清问题：名称变化不等于 mask 只覆盖对应部件

建议：先认定是同一物体，再确定它叫什么

不按名字合并；按跨帧表面对应建立物体 ID。

chair 不应自动产生第二个物体，water tank 也不应被当作 toilet 的同义词。

  2. 按实际覆盖判断整体与部件。112 的标签虽然是 water tank，当前 mask 却覆盖水箱与坐便器区域，不能直接把它当作纯水箱点云。只有其他观测确实分离出水箱、且得到多视角支持时，才记录“水箱属于这个马桶”。不能因为名字像部件就拆分，也不能因为两块点相邻就合并；单张大 mask 可能包错，需更多视角复核。
  3. 形成物体点云。将已关联观测映射到共享体素或表面邻域，合并重复采样；由多个有效视角支持的点组成稳定表面。边缘、只见一次或归属冲突的点单独保留为待确认，不直接混入最终点云。遮挡和漏检不计为反对票，相邻近似视角也不重复算作独立证据。
  4. 最后确定类别。挑选清晰、视角不同的 RGB＋mask 裁剪，再识别一次或人工核对。几何能支持“是同一个”，却不能单独证明“叫马桶”。本例用户已给出马桶这一人工参照；自动流程仍应复核 toilet，保留 chair、water tank、potty 原始标签。chair 是误判证据，water tank 的部件含义与 mask 范围不一致，不能直接当作部件结论，也不对三帧简单多数投票。
展开：关联和点归属具体怎么判断？

双向看覆盖。分别计算“A 的可靠可见点有多少得到 B 的 mask／表面支持”与反方向的比例。双向高覆盖支持同一表面观测；只有小块被大块覆盖，提示部件／局部观测候选，而非立即合并。可见共同表面太少时记为未知，不能用少数点的高比例作结论。

再看多视角归属。每个体素保存来源帧、mask 和物体候选的支持／冲突证据。只在视野内、未被遮挡且深度可信的位置检验；只投到 2D mask 内还不够。没有检测到该物体不等于背景，若有可靠的其他实体表面争用该点，则保留冲突。体素尺寸和匹配半径应按局部几何误差校准。

不丢原始数据。使用逐帧 NPZ 中的 mask 点，而非仅用展示用的抽样全局 PLY；沿用 mask_bits 的重叠归属及原始标签，另存派生物体结果。跨帧点不是天然共享同一索引，需要空间对应；重投影还需与点云一致的相机位姿、深度与图像裁剪，不能混用未修正的坐标。

跨帧看见的，究竟是不是同一个物体？

本轮聚焦物体身份、位置与类别的一致性，不把“得到点云”直接等同于“得到可交互资产”。

原问题 · 用户原文

我们来开放式的讨论一个问题，就是我想做的是一套能只接收视频作为输入，把视频中的场景重建成为可交互的simready场景的算法。

这个算法面对的一个重要的问题就是跨帧一致性的问题，同一个物体，在视角差别很大和拍摄时间差别很大的两帧中被拍到，很可能被赋予不同的类别名，因而被识别成不同的两个物体。

另外靠的相近两个同类物体也很在聚类时，因为类别一致而被聚类为一个物体。所以如何从视频中正确识别出所有物体，确定他们的位置和类别是个很困难的问题。你有什么思路？

核心判断：先建立身份，再统一名字

增量建档 ＋ 全局纠错，最后生成可交互资产。

模型每一帧给出的 mask 和类别，只是一条“看见了什么”的观测。系统需要另外维护“它是谁”的物体档案，让同一个物体可以积累不同名称，不同物体也可以拥有相同类别。

这不要求在线立即做最终决定。先允许临时身份和不确定关系，视频结束后再利用全部视角修正。

重新看这个问题，类别名变化不一定是错误：chair 和 armchair 可能只是描述粒度不同。真正需要避免的是把“名称变化”直接变成“物体数量变化”。

因此要分开四件事：类别名是属性，帧内 mask ID是观测编号，临时物体 ID是关联假设，全局物体 ID才代表最终确认的实体。

假设视频拍到了左椅子 A 和右椅子 B。下面是示意，不是当前实验的统计结果。

同物可以异名，异物也可以同名；归属应由观测证据决定。

理想结果是两个物体 ID、两份各自的几何、各自的类别证据，而不是按名字生成三个模型，或把两把椅子拼成一个模型。

建议方案：聚合观测，不直接按类别聚类点

  1. 01 · 收集逐帧观测

    图像、mask、局部几何、名称与置信度。

  2. 02 · 关联临时物体档案

    更新已有物体，或建立待确认的新身份。

  3. 03 · 纠错全局合并与拆分

    检查长时间回访、错误连边和类别冲突。

  4. 04 · 生成独立 SimReady 资产

    身份稳定后，再补几何和交互属性。

  1. 先建立统一空间中的观测。从视频估计相机与几何，把每张 mask 对应的可见表面放到同一坐标系；保留原帧、像素对应和不确定性。几何重估时应能重新投影，不能把早期漂移永久焊死。
  2. 再判断两次观测是否来自同一个物体。先按空间关系检索候选，再结合表面对应、多视角一致性、时序连续性和图像外观。类别只作辅助证据，不作为必须相等的条件；外观相似也不能单独证明身份。
  3. 用全视频证据纠正临时关联。保留原始观测和每次合并／拆分理由，允许撤销。不能因为 A 连 B、B 连 C，就在存在冲突时把 A、B、C 全部合成一个物体。
  4. 按物体融合位置、几何与语义。用多视角支持的表面估计位置和范围，而不是用单帧可见片段的质心当物体中心。类别按不同视角的证据加权，保留原始别名和候选细分类；连续相似帧不应重复计成大量独立证据。
每个物体档案至少保存

全局／临时 ID · 来源帧与 mask · 已观测表面点云 · 位置与范围 · 类别候选及置信度 · 合并／拆分历史。

这是建议的数据表达，不代表这些字段已经全部实现。最终补全网格应与真实观测点分开保存。

最重要的规则：同一、不同、暂时不知道

支持同一
在误差容许范围内有一致的三维表面对应；其他视角能把局部观测连接为同一整体；外观与可见性也相容。要多条证据互相支持。
支持不同
多个可靠视角清楚显示两个独立完整物体，或位置／表面归属存在难以解释的冲突。空间相近和类别相同不能抵消这些证据。
暂时不知道
看不到共同表面、严重遮挡、几何质量差或外观过于相似。没有重叠不等于不同；没有冲突也不等于同一。

特别注意：同帧的两个 mask 可能是重复检测，或“椅子／椅背”这样的整体与部件；一张大 mask 也可能错包两个物体。因此不能机械地把同帧不同 mask 判为不同物体，也不能把一次重叠判为同一物体。

第一版宜优先控制误合并：把两个物体混成一个，后面的形状和资产生成都会受污染；暂时多留一个待确认档案，通常更容易回退。但必须同时报告未解决比例，不能靠“全部不知道”获得表面的高准确率。

下一步：先验证“认对物体”，不要急着生成资产

建议先做一个小型关联诊断，再扩展到整个场景；本轮仅记录实验设计，不运行新聚类。

  1. 选困难样例。从已有场景选少量关键帧和 20–50 对 mask 观测，覆盖同物异名、相邻同名、长时间回访，以及重复／部件 mask。人工标为同一、不同或证据不足。
  2. 比较最小方案。对比“仅几何关联”与“几何＋多视角证据”，再看加入外观是否真正有帮助。先不把多个大模型堆在一起，也不预设某个相似度阈值天然正确。
  3. 记录可检查的结果。每一对都输出支持证据、反对证据和决策。留出部分样例不参与调阈值；分别报告误合并、误拆分和未决比例。对确定给出的 same／different 判断统计错误，人工也无法判断的样例单列。
  4. 再检验全局聚类。配对判断通过后，仍要检查是否出现错误连边造成的大簇、同一物体被拆成多个 ID，以及物体点云混入邻居表面。配对正确率高不等于全局身份正确。

这套思路能解决什么，还不能保证什么

  • 先限定静态室内扫描。第一版以完整物体为身份单位；动态物体需要额外区分物体运动与相机运动，柜门／抽屉等部件身份和关节层级留到后续。不能只靠固定空间位置追踪移动物体。
  • 视频没有看到的内容，不能当作已恢复。漏检的物体不会靠聚类凭空出现；相反两面没有连接证据时，身份也可能无法确定。隐藏表面补全属于带先验的推测，不是观测真值。
  • 只输入单目 RGB，不代表绝对尺度可保证。几何本身存在尺度歧义；学习到的米制深度或尺寸先验可以估计尺度，但不是可验证的物理保证。若引入已知尺寸、深度或其他传感器，应明确说明输入假设已经改变。
  • 实例点云不等于 SimReady。还需要独立网格、碰撞体、支撑关系、合理尺度，以及任务需要的关节和物理参数。尤其摩擦、质量和未展示的关节运动，不能从普通扫描视频直接保证，需要先验、假设或额外验证。
GT 边界必须单独记录

当前点云使用 GT 修正的 AMB3R 几何。可先用它隔离变量、诊断关联问题，但它仍可能有局部几何误差；后续必须在不使用 GT 修正的 RGB 重建上重测。前者通过，不能证明整个系统已满足“只接收视频”的目标。

参考思路，不直接照搬输入假设

  • MaskClustering · 官方项目：借鉴多视角共识与 mask 图聚类。官方代码说明的输入是 RGB-D 扫描与重建点云；它不是从纯 RGB 视频完成几何和 SimReady 的整套方法。
  • ConceptGraphs · 官方项目：借鉴对象级地图与跨视角增量关联。原方案使用带位姿的 RGB-D 图像；我们需要另行解决 RGB 几何、误差传播和可撤销身份关联。
